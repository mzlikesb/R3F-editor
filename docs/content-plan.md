# OUTPOST — 모두가 함께 지키는 행성 기지

## Context
`docs/spec.md`의 기술을 쓰되, 억지로 끼워 맞춘 데모가 아니라 **그 자체로 완결된 콘텐츠 하나**를 만든다.
콘셉트: 행성에 기지가 하나 있고, **접속한 사람 전원이 같은 기지를 본다.** 서버에서 모듈 고장이 나고,
누군가 수리하면 모든 사람 화면에 바로 반영된다. 기지는 사람들이 함께 살려두는 한 계속 가동된다.
→ WebSocket·서버 상태가 "보여주려고"가 아니라 콘텐츠에 진짜 필요해진다.

마감 2026-12-04(금). 저장소 github.com/mzlikesb/outpost .

**범위 원칙:** 방은 하나(로비·계정·닉네임·채팅 없음). 상호작용은 "수리"와 "부품 줍기" 2종(수리에 부품이 든다. #101 결정, 플랜 009). 스펙의 제외 목록(저장/계정/undo/기즈모/업로드) 유지.

## 첫 이정표 (완료: PR #9, 11/26)
**배포 URL에서 폰으로 발전기(큐브)를 수리하면 PC에서도 경고등이 꺼진다.**
모델 작업 전에 선택·패널·서버 상태가 끝까지 도는지 큐브 하나로 먼저 검증한다.

## 콘텐츠 루프
1. 접속 → `/api/base` 스냅샷으로 첫 화면, 이어서 WS 연결. 상단 HUD는 두 줄이다. 윗줄 `가동 3시간 12분`(정전 중에는 `가동 기록 끊김 · 최장 5시간`), 아랫줄 `함께 고친 7회 · ◆ 3명 접속 중`(006 C.19, #59). 폰에서 한 줄에 다 안 들어가서 둘로 나눴다. 다른 접속자가 있으면 `접속 중` 앞에 따뜻한 흰색 다이아몬드가 붙는다(기지 위 드론 불빛과 같은 색, #107). 윗줄 `가동` 뒤에 부품 칩 `부품 3/5`(상한이면 `부품 가득`)가 들어간다(009 R4, #114)
2. 센서값(발전기 kW·산소 %·온실 ℃·통신 %·기압 kPa)은 **클라이언트가 `shared/sensors.ts`로 계산**한다. 서버는 센서를 보내지 않고, 고장 상태와 시각에서 파생해 매 순간 같은 값이 나온다(006 B.8, #47). DO는 접속자가 있는 동안 20~40초 간격으로 고장을 주입한다 → 수치 악화, 모듈 붉게 펄스. **고장·선택 모듈에만** 모듈 위 drei `<Html>` 배지로 이상 수치 1줄(예: `⚠ 92℃`) → 첫 화면부터 3D 오버레이가 보임(전 모듈 상시 표시는 모바일 성능상 안 함)
3. 클릭 → 카메라가 모듈로 날아감 → 패널에 수치·추이 → [수리] 홀드(창고 부품 1개가 든다). **홀드 버튼은 3D가 아닌 HTML 패널**에 둬서 카메라 제스처와 분리. 홀드 중 다른 사람이 먼저 고치면(`repaired` 메시지) 즉시 홀드 해제 + "누군가 먼저 고쳤어요" 짧은 피드백
4. 수리는 `faultId`로 서버에 전송 → **같은 고장은 한 번만 완료**(두 탭 동시 수리해도 누적 +1, 부품도 한 번만 든다) → 전원에 반영, 다른 사람 수리는 링 핑으로 보임. 창고가 0이면 서버가 `repairRejected{noParts}`로 거절한다(009, #114)
5. **부품 줍기**(고장이 없는 시간의 할 일, #101): 서버 시각 10초마다 슬롯 번호에서 정해지는 자리에 조각 하나가 뜨고, 누르면 공용 창고에 +1(상한 5). 창고는 모두가 같이 쓴다. 조각 위치는 슬롯 번호만으로 정해져 서버가 저장하지 않는다(`shared/parts.ts`). 상세는 `docs/plans/009-parts.md`
6. 방치된 고장이 쌓이면 정전 → 조명 꺼지고 비상등. **정전 중에도 발전기는 선택·수리 가능** → 수리 시 조명 복구, 새 가동 기록 시작. "최장 가동 기록" 보존

### 상태 규칙
- **무인 시간:** alarm은 접속자가 있을 때만 걸고 0명이 되면 지운다. 다음 접속 시 마지막 저장 시각으로 경과를 계산하되 **고장은 최대 2~3개까지만 쌓이고 정전 직전에서 멈춘다** → 돌아온 사람은 "고쳐야 할 기지"를 보고, 가동 기록은 계속 쌓임
- **의도된 리듬(#85 측정, 008-1):** 비어 있던 기지에 혼자 들어오면 고장 2개가 있고, 아무것도 안 하면 다음 고장 하나(20~40초)로 정전이 온다. 손이 가면 막을 수 있다 — 혼자 들어온 첫 방문자가 약 20초에 둘 다 고쳐 정전을 막았다(PR #104 플레이테스트). 재고장 간격(`REFAULT_MIN_MS`/`REFAULT_MAX_MS`)은 그대로 둔다
- **첫 방문 보장:** 접속 시 고장이 하나도 없으면 바로 고칠 수 있는 고장 1개를 만든다
- **중도 합류/재연결:** WS 연결 시 항상 전체 스냅샷부터 보냄
- **영구 저장(DO SQLite):** 고장 목록·가동 시작 시각·누적 수리·최장 기록·정전 이력·마지막 저장 시각·부품 수(`parts`)·마지막으로 주운 슬롯(`lastPartSlot`)만. 센서값은 저장 안 하고 고장 상태에서 파생
- **정전 집계 멱등:** alarm 재시도로 같은 정전이 두 번 기록되지 않게 정전 id/시각으로 중복 방지 ([Alarms 문서](https://developers.cloudflare.com/durable-objects/api/alarms/))
- **끊김:** 마지막 서버 상태 유지 + "재연결 중" 표시 + 수리 버튼 잠금 → 재연결 시 스냅샷 적용 후 활성화
- 메시지: 원본은 `shared/protocol.ts`의 `ServerMessage`·`ClientMessage`다(현재 `PROTOCOL_VERSION = 3`, 프로토콜 1 소켓은 4400으로 닫는다). 여기에 열거하지 않는다. 센서 메시지는 없다(위 2)

## 피드백 이펙트
깊이는 얇게, 손맛은 진하게. 1~4는 005(#45)에서 들어갔고, 5는 006(#47)의 정전·복구(비상등, 패널 불빛 순차 점등은 #54)로 들어갔다. 6~8은 008(#100 셰이크·콤보, #108 색수차·상시 Noise)에서 들어갔다. 넣는 순서:
1. **수리 홀드**: 원형 게이지 + 미세 진동 → 완료 순간 흰 플래시 + 스케일 펀치(스프링)
2. **다른 사람 수리 링 핑** + HUD 누적 수리 롤링 카운트업 — 공유 기지라는 걸 알게 해주는 연출이라 앞순위
3. **완료 버스트**: 스파크 파티클(InstancedMesh 풀) + 가산 블렌딩 글로우 스프라이트(이 버스트 자체는 스프라이트라 후처리 없이 그린다, 005 C.9. 화면 전체 Bloom은 008에서 따로 들어갔다) + `+1 REPAIR` 팝업
4. **상태 전환 색 웨이브**: 빨강→초록 복귀 시 emissive가 표면을 훑음
5. **정전/복구 연출**: 조명 소등 → 빨간 비상 회전등 → 복구 시 순차 점등
6. **카메라 셰이크**(`src/scene/CameraShake.tsx`, #100)
7. **콤보** `x2 x3`(`src/combo.ts`, #100)
8. **색수차/노이즈**(정전 때 색수차 발동, 상시 Noise, #108)

하지 않기로 한 것: 포커스 이동 오버슈트(CameraControls 보간과 다툰다), 효과음(008 플랜 "하지 않는 것").
구현: `maath/easing`(스프링·보간). 후처리는 008에서 정했다(#99 비교 뒤 사용자 결정): 모든 기기 기본으로 컴포저 `N8AO → Bloom → 색수차 → Vignette → Noise → ToneMapping → SMAA`를 쓴다(`src/scene/post/PostStack.tsx`, #108). Outline 후처리 패스만 쓰지 않는다. 선택 표시는 선택 링과 inverted hull 아웃라인이다(#104). 터치 기기는 파티클 수를 절반으로 줄인다.

## 구조
파일 목록은 `ls src src/scene src/ui worker shared`가 원본이다. 역할 나눔만 적는다.
```
src/            클라이언트 로직(store·sync·hold·feedback·combo·parts). 순수 로직은 *.test.ts로 검증
  scene/        그리기(R3F): 모듈·지면·바위·소행성대·하늘·조명·카메라·셰이크·부품 조각·접속자 불빛, 팔레트(palette.ts)
  scene/post/   후처리 스택(별도 청크로 지연 로드)
  scene/fx/     수리 연출·이름표
  net/          통신(socket·api)
  ui/           HTML 패널(HUD·패널·기록·토스트·부품 비행 연출)
worker/         Worker + DO: BaseRoom.ts(상태 소유·alarm·멱등 수리·부품), state·holds·broadcast·rateLimit·socketId 순수 로직,
                legacy.ts(프로토콜 1 소켓용 변환), index.ts(/api/base, /api/history, /ws → DO)
shared/         protocol.ts(메시지 타입, 클라·워커 공용 원본), sensors.ts(센서 계산), parts.ts(부품 슬롯·상한)
wrangler.jsonc  assets(dist, SPA fallback) + DO 바인딩 + SQLite migration
public/models/*.glb (Draco), public/draco/, scripts/compress.sh
```
의존성 목록의 원본은 `package.json`이다. `@react-three/postprocessing`은 `scene/post/`에서 쓴다(008, #108).
에셋: CC0 로우폴리 SF 팩(Kenney Space Kit 등) + Poly Haven HDRI.

## Verification
- 로컬 `npm run dev` + `wrangler dev`, **탭 2개**: 한쪽 수리 → 다른 쪽 즉시 정상 복귀 / 두 탭 동시 수리 → 누적 +1만
- 수리 중 한 탭 새로고침·중도 접속 → 최신 상태로 시작
- DO storage: 탭 다 닫고 시간 지나 재접속 → 고장 2~3개, 정전 아님, 가동 기록 유지. 고장 방치 → 정전 1회만 기록 → 발전기 수리로 복구·새 기록
- WS 끊기(DevTools offline) → "재연결 중"·수리 잠금 → 복귀 시 스냅샷 적용
- Network: GLB에 `KHR_draco_mesh_compression`, 디코더가 `/draco/`에서 로드, `/api/base` 200 후 WS
- 성능 HUD: 운석 수천 개가 소수 드로우콜, 폰 실기 FPS
- 홀드 중 다른 탭에서 먼저 수리 → 홀드 즉시 해제·피드백 / 폰에서 홀드해도 카메라가 안 돌아감

- 탭 다 닫으면 alarm이 멈추는지(Workers 대시보드 요청 수) 확인
- `npm run build` 통과, 배포 URL에서 PC+폰 동시 접속 동기화
