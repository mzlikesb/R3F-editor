## 플랜 리뷰에서 넘어온 항목

플랜 리뷰는 3턴을 채웠다(`11bc79f` → `2b719b4` → `6d3296f`). 그 뒤 지적은 플랜 파일을 고치지 않고 아래 수용 기준으로 넘긴다(`AGENTS.md` 3턴 규칙). 플랜 본문과 이 절이 다르면 **이 절이 이긴다**.

### R1. 조각은 세로 폰 전체 시점에서 보이고 탭할 수 있는 곳에만 떨어진다 (neon 3턴 막는 문제 1)

- `partPosition(slot)`의 후보 위치를 "`BOUNDS` 안 빈 땅"보다 좁힌다. 기준은 **세로 폰 전체 시점의 안전 영역**이다. 다음 세 조건을 모두 만족하는 곳만 후보로 둔다.
  - 390x844·360x780·320x568 전체 시점 카메라(`framing.ts`·`cameraPath.ts`의 `overviewPose`)로 투영했을 때 화면 안에 있다.
  - 위 HUD 띠와 아래 UI 띠를 뺀 영역 안에 있다.
  - 모듈 화면 사각형(탭 상자 투영 + 여유)과 겹치지 않고, 모듈 뒤에 가리지 않는다. 카메라에서 조각까지 가는 선이 모듈 탭 상자를 지나지 않아야 한다.
- 후보 격자는 미리 계산해 두고, `slot` 해시로 그중 하나를 고른다. 결정적이어야 한다.
- 테스트: 모든 후보가 세 화면에서 위 조건을 만족한다. PC 1280x800에서도 화면 안에 있다.
- Preview 폰 확인 항목: 조각 여러 칸이 모두 보이고 탭할 수 있는가.

### R2. 프로토콜 1 소켓과 롤백 파싱 순서 (neon 3턴 막는 문제 2)

- **프로토콜 1 소켓**: 009-2(`PARTS_REQUIRED = true`)부터 서버는 `?protocol` 없이 붙은 소켓을 곧바로 닫는다. 닫는 코드는 `4400`, 이유는 `update required`다. 프로토콜 1 클라이언트는 11/27 이전 빌드라 새로고침하면 새 클라이언트를 받는다. 009-1에서는 지금처럼 레거시 스냅샷을 보낸다.
- **파싱 순서**: 프로토콜 3 파서는 `protocol` 값을 **먼저** 본다. 3이 아니면 필드 검사 없이 비호환으로 판정해 수리 잠금과 새로고침 배너를 띄운다.
- 테스트: `parts`·`lastPartSlot`이 없는 `protocol: 2` 스냅샷이 비호환 판정(배너)으로 가고, 파싱 실패로 조용히 무시되지 않는다.

### R3. 옛 코드 호환 검증의 위치 (neon 3턴 제안 1)

- **상시 테스트**: 옛 코드를 복제하지 않는다. 지금 main 서버가 실제로 내보내는 메시지와 저장본을 **고정 JSON 픽스처**로 남긴다. 픽스처에 새 필드를 붙여도 지금 파서·`loadState`가 기존 필드를 그대로 돌려주는지 본다.
- **1회 QA**: 009-1 QA가 직전 main 커밋을 체크아웃해 두 가지를 확인하고 리포트에 적는다.
  - 옛 클라이언트를 새 서버에 붙이는 경우
  - 새 저장본을 옛 `loadState`로 읽고 쓰는 경우(롤백)
- 009-2 QA도 같은 방식이다. 옛 빌드(프로토콜 2)와 새 서버(프로토콜 3)를 짝지은 세션, 그리고 그 반대 방향을 확인한다.

### R4. HUD 자리와 상한 표시 (neon 3턴 제안 2)

- `부품 N/5`는 아랫줄 끝에 붙이지 않는다. 윗줄 `가동 …` 오른쪽, `≡ 기록` 버튼 앞에 작은 칩으로 둔다. 360·320 폭에서 HUD가 줄바꿈되거나 잘리지 않아야 한다(스크린샷 확인).
- 상한(5/5)이면 칩을 강조색으로 바꾸고 `부품 가득`으로 표시한다.

### R5. 경계 조건 (neon 3턴 제안 3)

- **검사 순서**: 수리 요청은 `faultId` 유효성(존재하는 고장인가)을 먼저 보고, 그다음 `parts >= 1`을 본다. 마지막 부품 1개로 두 사람이 **같은 고장**을 고치면, 두 번째 요청은 `noParts`가 아니라 이미 고쳐진 고장으로 무시된다. 서버 테스트를 추가한다.
- **줍기 대기 즉시 해제**: 아래 경우에는 1.5초를 기다리지 않고 대기 상태를 바로 푼다.
  - 내가 탭한 칸에 대해 `parts { mine: false }`(남이 먼저 주움)를 받았을 때
  - 상한에 도달했을 때
  - 재연결 `snapshot`을 받았을 때
  - 연결이 끊긴 동안에는 줍기 탭을 받지 않는다(수리 잠금과 같다).
- **다음 조각 링 핑 예약 취소**: 아래 경우 예약해 둔 링 핑을 취소한다.
  - 다음 조각이 떨어지기 전에 창고가 1 이상이 됐을 때
  - 사용자가 모듈을 선택했을 때
- **시계 앞섬 허용**: 서버는 `collect`의 `slot`을 지금 칸 −1부터 +1까지 받는다. +1은 지금 칸이 끝나기 1초 안일 때만 받는다. 클라이언트는 재연결 때와 `parts`·`repaired` 메시지를 받을 때마다 서버 시각 오프셋을 갱신한다. 이 메시지들에는 `serverNow`를 싣는다.
