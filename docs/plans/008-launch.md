# 008 — 출시: 고른 게 보이고, 기지가 한 톤으로 보인다

- 브랜치: `feat/008-launch`
- 등급: large
- 관련 이슈: Refs #91, Refs #82
- 마일스톤: M5 출시
- 상태: 플랜 리뷰

## Context

M2~M4에서 기지·공유 상태·성능을 만들었다. 남은 문제는 셋이다.

1. **고른 게 모양으로 안 보인다**(#91). 모듈을 누르면 카메라가 붙고 이름표가 뜨지만 모듈 자체는 그대로다. 무엇을 고르고 있는지는 카메라 움직임으로만 알 수 있다.
2. **화면이 한 톤이 아니다**(#82). 폰 첫 화면은 아래 35~40%가 빈 바닥이다. 태양광 패널 밭의 남색과 밝은 테두리가 모듈과 시선을 다툰다.
3. **이펙트 6~8이 아직 없다**(`docs/content-plan.md` 피드백 이펙트). 수리 1~5는 있다.

이 PR은 새 서버 상태를 만들지 않는다. 클라이언트 상태는 하나(콤보 카운트, C.2)만 늘린다. 손맛과 보이는 품질만 다룬다(`AGENTS.md` "읽을 상태를 늘리기 전에 손맛 먼저").

경험 원칙: 3(들어오자마자 알 수 있다 — 첫 화면에 기지가 꽉 차고, 고른 것이 보인다), 4(손맛은 진하게), 5(폰이 기준 화면이다 — 폰은 후처리 없이도 선택이 보인다).

## 만들 것

### A. 아트 방향 (#82)

1. **팔레트를 한 곳에 둔다**: `src/scene/palette.ts`에 의미별 색을 모은다. 고장(빨강), 수리 완료·상태등(초록), 선택(새 색), 비상등, 패널 켜짐·꺼짐이 들어간다. 지금 흩어져 있는 색 상수(`fx/StatusLight`, `fx/shared`, `panels.ts` 등)는 여기를 참조한다.
   - 선택 색은 빨강·초록과 겹치지 않는 색이다(시안 계열 후보). 고장 모듈을 선택해도 빨간 펄스와 선택 표시가 구분돼야 한다(#91 걸리는 것 3).
   - 테스트: 선택 색과 고장·수리 색의 색상(hue) 거리가 최소값 이상이다.
2. **폰 첫 화면 프레이밍**: 세로 화면에서 모듈 5개가 화면 세로 가운데 영역을 채운다. 아래 빈 바닥은 화면의 20% 이하로 줄인다.
   - `framing.ts`의 폭 맞춤 계산과 `OVERVIEW_MARGIN`·극각을 세로 화면 기준으로 다시 잡는다.
   - 테스트: 390x844·360x780·320x568에서 모듈 점들의 화면 위치를 투영하고, 가장 아래 점과 화면 아래 사이 여백이 20% 이하인지 본다. 이름표·배지가 화면 위로 잘리지 않는지도 본다(기존 `framing` 테스트 확장).
   - 소행성대 시선 조건(`asteroids.test.ts`)은 그대로 통과해야 한다.
3. **거리 안개**: `scene.fog`를 선형 안개로 넣고 하늘 그라디언트 아래쪽 색에 맞춘다. 패널 밭·바깥 바위가 뒤로 물러나 보이게 한다. 후처리가 아니므로 모든 등급에 켠다.
   - 정전 때는 안개 색이 어두운 하늘색으로 같이 바뀐다.
   - `toneMapped: false` 재질(글로우·스파크·상태등·패널 램프)은 `fog: false`로 둬서 밝기를 유지한다.
4. **패널 밭 톤**: 패널 본체의 채도·명도를 낮추고 테두리 대비를 줄인다. 모듈이 시선의 주인이 되게 한다. 정전 소등·순차 점등(#54)은 그대로다.
5. #82의 제안(막지 않음) 중에서는 **선택 시 고장 문구 중복**만 고친다. 패널과 이름표에 같은 문구가 두 번 나오지 않게 한다. 나머지 제안은 이 PR에서 하지 않는다.

### B. 선택 아웃라인과 후처리 (#91)

1. **등급별 고정**: 후처리 스택(`EffectComposer`)은 **desktop 등급에서만, 시작할 때 한 번** 붙인다. 품질 사다리는 계속 "셰이더 재컴파일 없는 것만 런타임에 바꾼다"는 전제를 지킨다(007 C.9). 그래서 컴포저는 런타임에 붙이거나 떼지 않는다. mobile 등급은 컴포저 없이 지금 렌더러 그대로 간다.
2. **지연 로드**: 컴포저와 효과 코드는 별도 청크로 desktop일 때만 불러온다. 초기 JS 예산 450KB(`scripts/bundle-budget.mjs`)를 지키기 위해서다. 청크를 불러오기 전과 실패했을 때는 mobile 표현으로 선택을 보여준다.
3. **desktop 선택 아웃라인**: `@react-three/postprocessing`의 `Selection`/`Select` + `Outline`으로 선택한 모듈에만 선택 색(A.1) 아웃라인을 그린다. 선택을 바꾸면 아웃라인도 따라 옮겨진다. 선택을 풀면 사라진다.
   - 고장 모듈을 고르면 빨간 이미시브 펄스는 그대로 두고, 아웃라인은 선택 색으로 그 바깥에 그린다.
4. **mobile 선택 표현**: 후처리 없이, 선택한 모듈 바닥 링(floor ring)을 선택 색으로 밝게 바꾸고 천천히 맥동시킨다. 링 재질은 이미 있는 것을 재사용하고 새 셰이더는 만들지 않는다. desktop에서도 아웃라인과 함께 켠다(두 등급이 같은 언어를 쓴다).
5. **톤 매핑 이전**: 컴포저가 붙으면 톤 매핑은 렌더러가 아니라 `ToneMapping` 효과가 맡는다. 렌더러 쪽 톤 매핑과 같은 방식·노출로 맞춘다. 그러면 `toneMapped: false` 재질 5곳(`fx/Glow`, `fx/StatusLight`, `fx/Sparks`, `fx/shared`, `SolarPanels` 램프)이 desktop과 mobile에서 같은 밝기로 보인다.
   - 확인은 폰·PC 스냅샷 대조로 한다. 같은 장면에서 글로우·스파크·상태등·램프가 어느 쪽에서도 눈에 띄게 밝거나 어둡지 않아야 한다.
6. **공간감 효과**: desktop은 `Vignette` 하나만 약하게 넣는다. SSAO는 넣지 않는다(드로우콜·깊이 패스 비용 대비 이득이 작고, 안개 A.3이 원근을 맡는다).
7. **안티에일리어싱**: 컴포저를 쓰면 캔버스 MSAA가 꺼진다. 컴포저의 `multisampling`으로 대신한다. 값은 성능 측정으로 정한다.

### C. 이펙트 6~8

1. **카메라 셰이크(6)**: 내가 수리를 끝낸 순간에만 짧게(0.25초 안팎) 흔든다. 남이 고친 수리나 정전에는 흔들지 않는다. `prefers-reduced-motion`이면 끈다.
   - 진폭·감쇠는 순수 함수 `shakeOffset(elapsed)`(테스트: 0에서 시작, 끝나면 0, 최대 진폭 이하).
   - 흔들림은 CameraControls의 상태를 바꾸지 않고, 렌더 직전 카메라 위치에 더했다가 렌더 뒤 되돌린다(`useFrame` 안에서 할당하지 않는다).
   - 포커스 이동 오버슈트는 하지 않는다. CameraControls의 짧은 경로 보간(M4에서 고침)과 다투기 때문이다.
2. **콤보(7)**: 내가 연달아 고치면 `x2`, `x3`을 수리 완료 팝업(`+1 REPAIR`) 옆에 띄운다.
   - 연속의 기준: 이전 내 수리 완료에서 **15초 안**에 다음 수리를 끝낸 경우. 기준값은 플레이테스트 뒤에 조정할 수 있게 상수로 둔다.
   - 클라이언트 표시만이다. 서버·저장·HUD 누적 수리 수는 바뀌지 않는다.
   - 순수 함수 `nextCombo(prev, now)`(테스트: 첫 수리 1, 창 안 연속 증가, 창 밖 1로 리셋, 남의 수리는 영향 없음, 재연결해도 그대로).
3. **색수차(8)**: 정전이 시작되는 순간 desktop에서만 0.4초 동안 `ChromaticAberration`을 세게 냈다가 0으로 줄인다. mobile은 기존 정전 연출(소등·비상등)만 쓴다. 노이즈와 효과음은 넣지 않는다.

## Verification

- 단위 테스트: 팔레트 색 거리, 폰 프레이밍 여백, `shakeOffset`, `nextCombo`, 등급별 컴포저 결정(desktop만, 시작 시 한 번)
- 기존 테스트 통과: `framing`·`asteroids`(시선 조건)·`quality*`·`labelRules`
- 번들: 초기 JS gzip 450KB 이하. 후처리 청크는 지연 청크 합계로 PR 본문에 적는다
- 성능(PR 본문에 측정값): desktop 60fps, 폰 30fps 이상, 드로우콜 100 이하. 컴포저 켠 desktop에서 프레임 시간 증가분
- Preview 폰·PC 스냅샷(`scripts/snapshot-critique.sh`)과 페르소나 플레이테스트(`playtest` 스킬)를 돌린다. 확인할 것은 셋이다.
  - 폰 첫 화면 빈 바닥이 줄었는가
  - 선택한 모듈이 모양으로 보이는가(desktop 아웃라인, 폰 링)
  - 고장·수리·선택이 서로 구분되는가
- 정전: 안개 색 전환, desktop 색수차 한 번, 복구 뒤 원래대로
- `prefers-reduced-motion`에서 셰이크가 없다
- 사용자가 Preview를 폰·PC로 직접 확인
