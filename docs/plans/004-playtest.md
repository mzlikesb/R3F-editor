- 브랜치: `chore/023-playtest`

## Context

기능 PR의 Preview는 지금 사용자가 폰·PC로 직접 확인한다. 3D 화면을 처음 본 사람이 설명 없이 무엇을 하는지 확인할 장치가 없다.

사전 정보가 없는 페르소나 에이전트 3명이 Preview URL만 받아 브라우저로 플레이하고, 본 것과 한 것만 리포트로 남긴다. 기획 에이전트가 리포트를 읽고 지적을 이슈로 올린다. 헤드리스 Chromium에서 렌더링과 클릭·홀드가 된다는 것은 #22에서 확인했다(Playwright 스크립트 기준).

경험 원칙 1·3을 확인하는 장치다. 다만 페르소나에게는 원칙을 주지 않는다. 원칙을 몰라도 느껴지는지가 확인 대상이다.

## 만들 것

0. **사전 확인(구현 첫 작업)**: Playwright MCP를 페르소나와 같은 실행 조건으로 한 번 띄워 아래를 확인한다. 하나라도 안 되면 멈추고 사용자에게 알린다.
   - `--caps vision`의 좌표 도구로 3D 캔버스의 큐브를 누를 수 있다(`browser_mouse_click_xy`).
   - 수리 버튼을 1초 이상 누르고 있을 수 있다(`browser_mouse_down` → 대기 → `browser_mouse_up`).
   - 스크린샷에 WebGL 장면이 그려진다.
   - `--bare`와 로그인 인증이 함께 되는지 확인한다. 되면 `--bare`로 확정하고, 안 되면 `--setting-sources`를 비우는 쪽으로 확정한다. 분기는 남기지 않는다.
1. **`scripts/playtest.sh <URL> [페르소나…]`**: 페르소나 하나당 독립된 `claude -p` 프로세스를 띄운다. 기본값은 3명 전원이고, **3명을 동시에** 돌린다. 같은 기지에 동시에 접속하므로 접속자 수와 남의 수리가 실제로 보인다.
   - **준비 단계(병렬 실행 전 1회)**: 고정 버전 `@playwright/mcp`를 받고 Chromium 바이너리가 있는지 점검한다. 동시 첫 실행의 다운로드 경합을 피하기 위해서다.
   - 작업 폴더는 실행마다 `mktemp -d`로 만든 빈 폴더다. 저장소 밖이라 `CLAUDE.md`·`AGENTS.md`가 로드되지 않고, 메모리도 새로 시작한다. 실행에는 `--no-session-persistence`를 준다.
   - 내장 도구는 끈다(`--tools ""`). MCP는 `--strict-mcp-config --mcp-config <생성한 json>`으로 Playwright만 쓴다.
     - 허용 범위는 `--allowedTools "mcp__playwright__*"`이고, `--disable-slash-commands`로 사용자 스킬도 끈다.
   - Playwright MCP는 `npx @playwright/mcp@<고정 버전>`으로 받고 `package.json` 의존성에는 넣지 않는다. 옵션은 `--isolated --headless --caps vision`과 페르소나별 `--output-dir`이다.
     - 기기는 페르소나 문서 머리의 `device:` 값에서 읽는다. 값이 `iPhone 13`이면 `--device`로 넘기고(390×844, 터치), `1280x800`이면 `--viewport-size`로 넘긴다.
   - 프롬프트로는 **페르소나 문서와 리포트 형식만** 넘긴다. URL 말고는 이 작품에 대한 설명을 넣지 않는다.
   - 모델은 Sonnet이다.
   - **상한과 수거**: 프롬프트로 행동 횟수 예산을 주고, 예산이 끝나면 리포트를 쓰라고 한다. 그 뒤에 이중으로 막는다.
     - `--max-turns`는 예산보다 넉넉하게 둔다.
     - 시간 상한을 넘기면 스크립트가 프로세스 그룹째 종료한다. Chromium도 같이 정리된다.
     - 출력은 `--output-format stream-json`으로 받아 파일로 흘려 둔다. 정상 종료면 마지막 `result` 이벤트에서 리포트·`duration_ms`·`usage`를 꺼낸다.
     - 상한으로 끊기면 마지막 assistant 글을 리포트로 쓰고 머리에 `미완료(상한)`를 붙인다. 시간은 벽시계로 재고, 토큰은 이벤트의 `usage`를 `message.id`로 중복을 빼고 합친다.
     - 금액은 적지 않는다(#19와 같은 기준).
   - **스크린샷**: 찍는 수에는 제한이 없다. 페르소나는 상황을 보려고 필요할 때마다 찍는다. 리포트 항목마다 근거 스크린샷을 파일 이름으로 적고, 스크립트는 리포트가 가리키는 파일만 수거한다(페르소나당 많아야 6장). 나머지는 임시 폴더와 함께 지운다.
   - **보관**: 수거한 `report.md`와 인용된 스크린샷은 `docs/playtests/<YYYY-MM-DD>-<대상>/<페르소나>/`에 두고 **커밋한다**. PR 리뷰어와 #24가 같은 경로를 본다. 스크린샷은 PNG를 그대로 쓰고, 저장소가 커지는 게 문제 되면 그때 줄인다.
2. **페르소나 3종** `docs/playtests/personas/`:
   - `phone-casual.md`: 출퇴근길 폰으로 캐주얼 게임을 하는 사람(`device: iPhone 13`)
   - `pc-dev.md`: 3D·웹 기술에 관심 있는 PC 개발자(`device: 1280x800`)
   - `first-visitor.md`: 게임을 거의 안 하고 메신저로 링크를 받아 처음 들어온 사람(`device: iPhone 13`)
   - 각 문서에는 누구인지, 어떤 기기로 들어오는지, 얼마나 참을성 있는지만 쓴다. 이 작품에 대한 정보는 없다.
3. **템플릿**
   - `docs/templates/persona.md`, `docs/templates/playtest.md`
   - 리포트 형식은 다음과 같다:
     - 이게 뭐라고 생각했나
     - 처음 10초에 본 것
     - 한 것(순서대로)
     - 막히거나 헷갈린 곳
     - 좋았던 것
     - 다시 들어올 것 같은가
     - 각 항목의 근거 스크린샷 파일 이름
   - 질문은 중립으로 쓰고 원칙의 말을 쓰지 않는다.
4. **이슈 템플릿** `.github/ISSUE_TEMPLATE/playtest.yml`. `결정할 것` 칸을 맨 위에 두고, `playtest` 라벨은 템플릿이 붙인다.
5. **프로젝트 스킬 `.claude/skills/playtest`**: 기획 에이전트가 PR을 `stage:playtest`로 넘길 때 부르는 절차다.
   - 먼저 그 PR의 Preview URL로 스크립트를 실행한다. production URL로는 돌리지 않는다(실제 접속자 수와 기지 상태를 건드리므로).
   - 그다음 리포트를 읽고 지적을 원칙과 대조해 `playtest` 이슈로 올린다. 같은 지적이 둘 이상 나오면 하나로 묶는다.
   - 마지막으로 PR에 요약 코멘트를 단다. 요약에는 페르소나별 한 줄, 올린 이슈 번호, 시간과 토큰을 넣는다.
   - 접속했을 때 고장이 없었거나 다른 페르소나가 먼저 고친 것도 그대로 관찰 결과로 본다. 실제 플레이에서도 일어나는 일이다.
6. **`AGENTS.md`**: 워크플로우의 플레이테스트 줄과 완료 기준을 실제 흐름으로 바꾼다.
   - 이 PR에서는 "페르소나 플레이테스트 → 사용자가 Preview 확인"으로 적는다.
   - 첫 실행 리포트와 시간·토큰을 PR 코멘트로 보여 주고, 계속 쓸지는 사용자가 정한다. "사용자 확인만"으로 정해도 스크립트·스킬·템플릿은 남기고, 워크플로우 줄만 되돌린다.
7. **`CLAUDE.md`**: 역할별 스킬 절에 `기획: stage:playtest에서 playtest`를 넣는다.

## Verification

- 격리를 확인한다:
  - stream-json의 `init` 이벤트에서 도구 목록이 `mcp__playwright__*`뿐이다.
  - 페르소나에게 "지금 쓸 수 있는 파일이나 문서가 있나"를 물으면 없다고 답한다.
  - 플레이어 작업 폴더가 비어 있고 저장소 밖이다.
- **이 PR의 Preview URL**로 3명을 동시에 한 번 돌린다. Preview는 PR마다 DO 저장소가 따로라, 첫 접속 때 첫 방문 보장으로 고장이 하나 있다.
  - 3명 모두 `report.md`와 인용된 스크린샷을 남긴다.
  - 폰 페르소나 2명의 스크린샷이 세로 모바일 비율이다.
  - 실행 중 한 번이라도 HUD 접속자 수가 2 이상으로 찍힌 스크린샷이나 리포트 문장이 있다.
- 시간 상한을 짧게 줘서 한 번 끊어 본다. `미완료(상한)` 리포트가 남고, Chromium 프로세스가 남지 않는다.
- 리포트의 지적이 스킬 절차대로 `playtest` 이슈로 올라간다. 이슈 템플릿이 `결정할 것` 칸을 채운다.
- 실행 하나의 시간과 토큰이 리포트 머리와 PR 요약 코멘트에 남는다.
- `npm run test:hooks`가 통과한다. 스크립트의 인자 처리, `device:` 읽기, 상한 수거, 인용 스크린샷만 수거하는 경로는 가짜 `claude` 실행 파일로 테스트한다.
