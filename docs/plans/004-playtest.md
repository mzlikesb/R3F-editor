# 004 — 페르소나 플레이테스트

- 브랜치: `chore/023-playtest`
- 등급: large
- 관련 이슈: Closes #23

## Context

기능 PR의 Preview는 지금 사용자가 폰·PC로 직접 확인한다. 3D 화면을 처음 본 사람이 설명 없이 무엇을 하는지 확인할 장치가 없다.

사전 정보가 없는 페르소나 에이전트 3명이 Preview URL만 받아 브라우저로 플레이하고, 본 것과 한 것만 리포트로 남긴다. 기획 에이전트가 리포트를 읽고 지적을 이슈로 올린다. 헤드리스 Chromium에서 렌더링과 클릭·홀드가 된다는 것은 #22에서 확인했다(Playwright 스크립트 기준).

경험 원칙 1·3을 확인하는 장치다. 다만 페르소나에게는 원칙을 주지 않는다. 원칙을 몰라도 느껴지는지가 확인 대상이다.

## 만들 것

0. **사전 확인(구현 첫 작업)**: Playwright MCP를 페르소나와 같은 실행 조건으로 한 번 띄워 아래를 확인한다. 하나라도 안 되면 멈추고 사용자에게 알린다.
   - `--caps vision`의 좌표 도구로 3D 캔버스의 큐브를 누를 수 있다(`browser_mouse_click_xy`).
   - 수리 버튼을 1초 이상 누르고 있을 수 있다(`browser_mouse_down` → 대기 → `browser_mouse_up`).
   - 스크린샷에 WebGL 장면이 그려진다.
   - 위 셋을 `--device "iPhone 13"`에서도 확인한다. 고정 좌표가 아니라 **실제 `claude -p`가 스크린샷을 보고 좌표를 골라** 큐브와 수리 버튼을 누르게 한다. DPR 3에서 좌표가 어긋나면 폰 페르소나를 `--viewport-size 390x844` + 터치 없는 DPR 1로 바꾼다.
   - 3명을 동시에 띄워도 클릭·스크린샷이 시간 초과 없이 돈다(SwiftShader는 CPU로 그린다). 안 되면 시작에 시차를 둔다.
   - 페르소나가 스크린샷 결과에서 파일 이름을 알 수 있다.
   - 이 세션 안에서 `scripts/playtest.sh`가 `claude -p`를 띄울 때 부모 세션의 `CLAUDE*` 환경 변수를 비우고 띄워도 정상 실행된다.
   - `--bare`와 로그인 인증이 함께 되는지 확인한다. 되면 `--bare`로 확정하고, 안 되면 `--setting-sources`를 비우는 쪽으로 확정한다. 분기는 남기지 않는다. 어느 쪽이든 사용자 훅·전역 메모리·플러그인이 섞이지 않는지(`init` 이벤트와 `--probe` 답) 확인하고, 섞이면 멈춘다.
1. **`scripts/playtest.sh [--probe] [--serial] <URL> [페르소나…]`** (로컬 macOS 전제, 실제 실행은 CI에서 하지 않는다): 페르소나 하나당 독립된 `claude -p` 프로세스를 띄운다. 기본값은 3명 전원이고, **3명을 동시에** 돌린다. 같은 기지에 동시에 접속하므로 접속자 수와 남의 수리가 실제로 보인다.
   - `--probe`: 페르소나 대신 "지금 쓸 수 있는 파일·문서·도구를 모두 말해 달라"는 질문만 같은 격리 조건으로 한 명 보낸다. 격리 점검용이다.
   - `--serial`: 동시 대신 한 명씩 돌린다. 한도·부하로 동시 실행이 안 될 때 쓴다.
   - **대상 제한**: URL은 Preview 형식(`https://pr-<N>-outpost.<계정>.workers.dev`)이나 `localhost`만 받는다. production 호스트는 스크립트가 거절한다.
     - 실행 중에도 브라우저가 그 오리진 밖으로 나가지 못하게 Playwright MCP에 `--allowed-origins <대상 오리진>`을 준다.
   - **준비 단계(병렬 실행 전 1회)**: 고정 버전 `@playwright/mcp`를 받고 Chromium 바이너리가 있는지 점검한다. 동시 첫 실행의 다운로드 경합을 피하기 위해서다.
   - 작업 폴더는 실행마다 `mktemp -d`로 만든 빈 폴더다. 저장소 밖이라 `CLAUDE.md`·`AGENTS.md`가 로드되지 않고, 메모리도 새로 시작한다. 실행에는 `--no-session-persistence`를 준다.
   - 내장 도구는 끈다(`--tools ""`). MCP는 `--strict-mcp-config --mcp-config <생성한 json>`으로 Playwright만 쓴다.
     - 허용 도구는 와일드카드가 아니라 **사람이 할 수 있는 조작만** 목록으로 적는다. 이동(`browser_navigate`, `browser_navigate_back`), 화면 보기(`browser_snapshot`, `browser_take_screenshot`), 누르기·입력(`browser_click`, `browser_type`, `browser_press_key`, `browser_wait_for`, `browser_resize`), 좌표 조작(`browser_mouse_*`)이다.
     - `browser_evaluate`·`browser_network_requests`·`browser_console_messages`·`browser_file_upload`·탭 관리는 주지 않는다. `pc-dev`도 같다(개발자도 첫 방문엔 화면으로 판단한다).
     - `--disable-slash-commands`로 사용자 스킬도 끈다.
   - Playwright MCP는 `npx @playwright/mcp@<고정 버전>`으로 받고 `package.json` 의존성에는 넣지 않는다. 옵션은 `--isolated --headless --caps vision`과 페르소나별 `--output-dir`이다.
     - Chromium 실행 플래그는 따로 주지 않는다. #22에서 기본값으로 SwiftShader 렌더링이 됐다.
     - 기기는 페르소나 문서 머리의 `device:` 값에서 읽는다. 값이 `iPhone 13`이면 `--device`로 넘기고(390×844, 터치), `1280x800`이면 `--viewport-size`로 넘긴다.
   - 프롬프트로는 **페르소나 문서와 리포트 형식만** 넘긴다. URL 말고는 이 작품에 대한 설명을 넣지 않는다.
   - 모델은 Sonnet이다.
   - **상한과 수거**: 프롬프트로 행동 횟수 예산을 주고, 예산이 끝나면 리포트를 쓰라고 한다. 그 뒤에 이중으로 막는다.
     - 기본값: 행동 예산 25회, `--max-turns` 40, 시간 상한 10분. 환경 변수로 바꿀 수 있다.
     - 페르소나마다 자기 프로세스 그룹으로 띄운다(`set -m`). 시간 상한을 넘기면 그 그룹에 `TERM`을 보내고 5초 뒤에도 남아 있으면 `KILL`한다. Chromium까지 정리되고, 스크립트 자신은 영향을 받지 않는다.
     - 시간 상한은 bash 안에서 잰다(macOS에는 GNU `timeout`이 없다). 스크립트는 macOS 기본 bash 3.2에서 돈다.
     - `trap`으로 `EXIT`·`INT`·`TERM` 때 남은 그룹을 종료하고 임시 폴더를 지운다.
     - 출력은 `--output-format stream-json`으로 받아 파일로 흘려 둔다.
     - **정상 완료**는 `result` 이벤트의 subtype이 `success`일 때뿐이다. 그때 리포트·`duration_ms`·`usage`를 꺼낸다.
     - **턴 상한**(`result` subtype이 `error_max_turns`)과 **시간 상한**(`result` 없이 종료시킴)은 둘 다 미완료로 본다. 미완료와 그 밖의 오류 subtype은 아래 미완료 경로로 간다.
     - 미완료면 그때까지의 assistant 글 전체를 순서대로 이어 리포트로 쓰고 머리에 `미완료(상한)`를 붙인다. 시간은 벽시계로 재고, 토큰은 이벤트의 `usage`를 `message.id`로 중복을 빼고 합친다.
     - 금액은 적지 않는다(#19와 같은 기준).
     - 한 명이 실패해도 나머지는 수거한다. 실패한 페르소나는 리포트 자리에 `실패(사유)` 한 줄을 남기고, 하나라도 실패하면 종료 코드는 1이다. 한도·속도 제한(429)도 재시도 없이 `실패(사유)`로 남긴다. 다시 돌릴 때는 `--serial`을 쓴다.
     - 리포트 본문은 페르소나당 8,000자에서 자른다(PR 코멘트 한도 대비).
   - **스크린샷**: 찍는 수에는 제한이 없다. 페르소나는 상황을 보려고 필요할 때마다 찍는다. 리포트 항목마다 근거 스크린샷을 파일 이름으로 적는다.
     - 리포트에서는 스크린샷을 확장자를 포함한 basename을 백틱으로 감싸 적는다(템플릿에 명시). 스크립트는 그렇게 인용된 파일만 수거한다. basename만 인정하고, 인용 순서대로 앞의 6장까지다.
     - 미완료(상한)이거나 인용이 하나도 없으면 가장 최근 4장을 수거한다.
     - 나머지는 임시 폴더와 함께 지운다.
   - **보관: 저장소에 커밋하지 않는다.** 이미지가 히스토리에 영구히 쌓이고, 기능 PR 브랜치에 커밋하면 최종 SHA가 바뀌어 리뷰·Approve가 다시 돌아야 하기 때문이다.
     - 결과는 저장소 밖 `${PLAYTEST_RUNS_DIR:-$HOME/.local/share/outpost-playtests}/<대상>-<YYYYMMDD-HHMMSS>/<페르소나>/`에 둔다. `<대상>`은 Preview면 `pr-<N>`, localhost면 `local`이다. `report.md`와 인용된 스크린샷이다. 실행 시각이 폴더 이름에 들어가므로 재실행이 덮어쓰지 않는다.
     - 스크립트는 로컬 결과만 만든다. PR 코멘트는 스킬(4번)이 단다.
     - #24(neon 크리틱)는 같은 맥에서 이 폴더의 스크린샷을 읽는다.

4. **프로젝트 스킬 `.claude/skills/playtest`**: 기획 에이전트가 PR을 `stage:playtest`로 넘길 때 부르는 절차다.

   - 그다음 리포트를 읽고 지적을 원칙과 대조해 이슈로 올린다. 같은 지적이 둘 이상 나오면 하나로 묶는다.
     - 이슈는 `gh issue create`로 올린다. 본문 형식은 스킬에 적는다: 맨 위 `결정할 것` 줄, 어느 페르소나가 무엇을 보고 막혔나(리포트 인용), 관련 원칙, 대상 PR.
     - 라벨 `playtest`(이미 있다)와 그 PR의 마일스톤을 붙인다.
   - 마지막으로 PR에 요약 코멘트를 단다. 요약에는 페르소나별 한 줄, 올린 이슈 번호, 시간과 토큰을 넣고, 페르소나별 리포트 본문을 접어서(`<details>`) 붙인다. 이것이 공유되는 기록이다.
   - 지적이 하나도 없으면 이슈는 올리지 않고 요약 코멘트에 "지적 없음"으로 남긴다.
   - 접속했을 때 고장이 없었거나 다른 페르소나가 먼저 고친 것도 그대로 관찰 결과로 본다. 실제 플레이에서도 일어나는 일이다.

## Verification

- 격리를 확인한다:
  - stream-json의 `init` 이벤트에서 도구 목록이 허용 목록의 Playwright 도구뿐이다(`browser_evaluate` 없음).
  - `--probe` 답에 Playwright 말고는 없다. LLM 답이라 보조 확인이고, 판정은 `init` 이벤트로 한다.
  - 플레이어 작업 폴더가 비어 있고 저장소 밖이다.
- 순서를 고정한다: 아래 본 실행을 먼저 하고, 상한 끊기 확인은 그다음에 한다(첫 방문 고장은 처음 한 번만 확실하다).
- **이 PR의 Preview URL**로 3명을 동시에 한 번 돌린다. Preview는 PR마다 DO 저장소가 따로라, 첫 접속 때 첫 방문 보장으로 고장이 하나 있다.
  - 3명 모두 실행 폴더에 `report.md`와 인용된 스크린샷을 남긴다. 저장소 `git status`는 깨끗하다.
  - 폰 페르소나 2명의 스크린샷이 세로 모바일 비율이다.
  - 실행 중 한 번이라도 HUD 접속자 수가 2 이상으로 찍힌 스크린샷이나 리포트 문장이 있다.
- 시간 상한을 짧게 줘서 한 번 끊어 본다. `미완료(상한)` 리포트와 최근 스크린샷이 남고, Chromium 프로세스와 임시 폴더가 남지 않는다.
- production URL을 넘기면 스크립트가 실행 전에 거절한다. 실행 중 다른 오리진으로 이동하면 브라우저가 막는다.
- 리포트의 지적이 스킬 절차대로 `playtest` 라벨·마일스톤과 맨 위 `결정할 것` 줄을 갖춘 이슈로 올라간다. 지적이 없으면 요약 코멘트의 "지적 없음"으로 확인한다.
- 실행 하나의 시간과 토큰이 리포트 머리와 PR 요약 코멘트에 남는다.
- `npm run test:hooks`가 통과한다. 스크립트의 URL 거절, 인자 처리, `device:` 읽기, 완료 판정(success·`error_max_turns`·시간 상한), 인용 스크린샷 수거(basename·6장·최근 4장)는 가짜 `claude` 실행 파일로 테스트한다.
  - 테스트에서는 준비 단계(`npx`·Chromium 점검)를 환경 변수로 건너뛴다. 네트워크·브라우저 없이 CI(Linux)에서도 돈다.
