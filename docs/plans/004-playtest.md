## Context

기능 PR의 Preview는 지금 사용자가 폰·PC로 직접 확인한다. 3D 화면을 처음 본 사람이 설명 없이 무엇을 하는지 확인할 장치가 없다.

사전 정보가 없는 페르소나 에이전트 3명이 Preview URL만 받아 브라우저로 플레이하고, 본 것과 한 것만 리포트로 남긴다. 기획 에이전트가 리포트를 읽고 지적을 이슈로 올린다. 헤드리스 Chromium에서 렌더링과 클릭·홀드가 된다는 것은 #22에서 확인했다(Playwright 스크립트 기준).

경험 원칙 1·3을 확인하는 장치다. 다만 페르소나에게는 원칙을 주지 않는다. 원칙을 몰라도 느껴지는지가 확인 대상이다. 그래서 페르소나는 **화면(스크린샷)만 보고** 판단한다. DOM·접근성 트리는 주지 않는다.

## 만들 것

0. **사전 확인(구현 첫 작업)**: Playwright MCP를 페르소나와 같은 실행 조건으로 띄워 아래를 확인한다. 대상은 **로컬**(`npm run build` + `npx wrangler dev`)이다. Preview는 본 실행을 위해 처음 상태로 남겨 둔다. 하나라도 안 되면 멈추고 사용자에게 알린다.
   - 실제 `claude -p`가 스크린샷을 보고 좌표를 골라 3D 캔버스의 큐브를 누른다(`browser_mouse_click_xy`).
   - 수리 버튼을 1초 이상 누르고 있을 수 있다(`browser_mouse_down` → `browser_wait_for` → `browser_mouse_up`). 이 사이에 LLM 턴이 끼어 실제 누르는 시간이 몇 초로 늘어나는 것은 감안한다. 수리 반응 속도에 대한 체감은 이 장치로 평가하지 않는다.
   - 스크린샷에 WebGL 장면이 그려진다.
   - 위 셋을 `--device "iPhone 13"`에서도 확인한다. DPR 3에서 좌표가 어긋나면 폰 페르소나를 `--viewport-size 390x844`(DPR 1, 터치 없음)로 바꾼다. 바꿨으면 리포트 머리에 `기기 대체: DPR 1·터치 없음`을 남긴다(터치·롱프레스 문제는 이 실행으로 못 잡는다).
   - `--allowed-origins`를 켠 상태에서 WebSocket(`wss://` 같은 오리진)이 연결되고 HUD가 `연결됨`이 된다. Draco 디코더 같은 정적 리소스도 같은 오리진이라 막히지 않는다.
   - 스크린샷 결과에서 파일 이름을 알 수 있다. 모르면 `browser_take_screenshot`의 `filename` 인자로 `NN.png`을 직접 지정하게 한다.
   - 3명을 동시에 띄워도 클릭·스크린샷이 시간 초과 없이 돈다(SwiftShader는 CPU로 그린다). 안 되면 시작에 시차를 둔다.
   - 이 세션 안에서 실행기가 `claude -p`를 띄울 때 부모 세션의 `CLAUDE*` 환경 변수를 비우고 띄워도 정상 실행된다.
   - `--bare`와 로그인 인증이 함께 되는지 확인한다. 되면 `--bare`로, 안 되면 `--setting-sources`를 비우는 쪽으로 확정한다. 분기는 남기지 않는다. 어느 쪽이든 `init` 이벤트에 사용자 훅·전역 메모리·플러그인이 섞이지 않는지 확인하고, 섞이면 멈춘다.
1. **실행기 `scripts/playtest.mjs`**(Node 26, 의존성 추가 없음)와 진입점 `scripts/playtest.sh [--serial] <URL> [페르소나…]`(Node를 부르기만 한다): 페르소나 하나당 독립된 `claude -p` 프로세스를 띄운다. 기본값은 3명 전원을 **동시에** 돌린다. 같은 기지에 동시에 접속하므로 접속자 수와 남의 수리가 실제로 보인다.
   - 파싱·자르기·정렬·시간 상한·프로세스 종료를 모두 Node로 한다. `jq`·GNU 유틸리티·bash 버전에 기대지 않으므로 macOS와 Linux CI에서 같게 돈다.
   - `--serial`: 동시 대신 한 명씩 돌린다. 한도·부하로 동시 실행이 안 될 때 쓴다.
   - **대상 제한**: URL은 Preview 형식(`https://pr-<N>-outpost.<계정>.workers.dev`)이나 `localhost`만 받는다. production 호스트는 거절한다. 실행 중에도 브라우저가 그 오리진 밖으로 나가지 못하게 Playwright MCP에 `--allowed-origins <대상 오리진>`을 준다.
   - **준비 단계(병렬 실행 전 1회)**: 고정 버전 `@playwright/mcp`를 받고 Chromium 바이너리가 있는지 점검한다. 동시 첫 실행의 다운로드 경합을 피하기 위해서다.
   - 작업 폴더는 실행마다 새로 만든 빈 임시 폴더다. 저장소 밖이라 `CLAUDE.md`·`AGENTS.md`가 로드되지 않고, 메모리도 새로 시작한다. 실행에는 `--no-session-persistence`를 준다.
   - 내장 도구는 끈다(`--tools ""`). MCP는 `--strict-mcp-config --mcp-config <생성한 json>`으로 Playwright만 쓴다. `--disable-slash-commands`로 사용자 스킬도 끈다.
   - **허용 도구**(이 목록만, 와일드카드 없음). 사람이 화면을 보고 할 수 있는 조작이다:
     - 이동: `browser_navigate`, `browser_navigate_back`
     - 보기: `browser_take_screenshot`
     - 좌표 조작: `browser_mouse_click_xy`, `browser_mouse_move_xy`, `browser_mouse_down`, `browser_mouse_up`, `browser_mouse_drag_xy`, `browser_mouse_wheel`
     - 키보드·대기: `browser_press_key`, `browser_wait_for`
     - 주지 않는 것: `browser_snapshot`(접근성 트리), ref 기반 `browser_click`·`browser_type`, `browser_resize`, `browser_evaluate`, 네트워크·콘솔 조회, 파일 업로드, 탭 관리. `pc-dev`도 같다
   - Playwright MCP는 `npx @playwright/mcp@<고정 버전>`으로 받고 `package.json` 의존성에는 넣지 않는다. 옵션은 `--isolated --headless --caps vision --allowed-origins <오리진>`과 페르소나별 `--output-dir`이다.
     - Chromium 실행 플래그는 따로 주지 않는다. #22에서 기본값으로 SwiftShader 렌더링이 됐다.
     - 기기는 페르소나 문서 머리의 `device:` 값에서 읽는다. `iPhone 13`이면 `--device`로, `1280x800`이면 `--viewport-size`로 넘긴다.
   - 프롬프트로는 **페르소나 문서와 리포트 형식만** 넘긴다. URL 말고는 이 작품에 대한 설명을 넣지 않는다.
   - 모델은 Sonnet이다.
   - **상한과 수거**: 프롬프트로 행동 횟수 예산을 주고, 예산이 끝나면 리포트를 쓰라고 한다. 그 뒤에 이중으로 막는다.
     - 기본값: 행동 예산 25회, `--max-turns` 40, 시간 상한 10분. 환경 변수로 바꿀 수 있다.
     - 페르소나마다 자기 프로세스 그룹으로 띄운다(Node `spawn`의 `detached`). 시간 상한을 넘기면 그 그룹에 `SIGTERM`, 5초 뒤에도 남아 있으면 `SIGKILL`을 보낸다. Chromium까지 정리된다. 실행기가 `SIGINT`·`SIGTERM`을 받아도 남은 그룹을 같은 방식으로 정리하고 임시 폴더를 지운다.
     - 출력은 `--output-format stream-json`으로 받아 파일로 흘려 둔다.
     - **정상 완료**는 `result` 이벤트의 subtype이 `success`일 때뿐이다. 그때 리포트·`duration_ms`·`usage`를 꺼낸다.
     - **미완료**: 턴 상한(`error_max_turns`), 시간 상한(`result` 없이 종료시킴), 그 밖의 오류 subtype. 그때까지의 assistant 글을 순서대로 이어 리포트로 쓰고 머리에 `미완료(사유)`를 붙인다. 시간은 벽시계로 재고, 토큰은 `미집계(미완료)`로 적는다.
     - 금액은 적지 않는다(#19와 같은 기준).
     - 한 명이 실패해도 나머지는 수거한다. 실패한 페르소나는 리포트 자리에 `실패(사유)` 한 줄을 남기고, 하나라도 실패하면 종료 코드는 1이다. 한도·속도 제한(429)도 재시도 없이 `실패(사유)`로 남긴다. 다시 돌릴 때는 `--serial`을 쓴다.
     - 리포트 본문은 페르소나당 8,000자에서 자른다(PR 코멘트 한도 대비).
     - 리포트 머리에는 실행 모드(`동시`·`시차 N초`·`순차`), 기기(대체했으면 그 사실), 시간·토큰을 적는다.
   - **스크린샷**: 페르소나는 상황을 보려고 필요할 때마다 찍는다. 리포트 항목에는 근거 스크린샷의 파일 이름을 적는다. 실행기는 `--output-dir`의 스크린샷을 **전부** 결과 폴더로 옮긴다(페르소나당 최신 20장까지, 넘으면 오래된 것부터 버린다). 리포트 인용을 파싱해서 고르지 않는다.
   - **보관: 저장소에 커밋하지 않는다.** 이미지가 히스토리에 영구히 쌓이고, 기능 PR 브랜치에 커밋하면 최종 SHA가 바뀌어 리뷰·Approve가 다시 돌아야 하기 때문이다.
     - 결과는 저장소 밖 `${PLAYTEST_RUNS_DIR:-$HOME/.local/share/outpost-playtests}/<대상>-<YYYYMMDD-HHMMSS>/<페르소나>/`에 둔다. `<대상>`은 Preview면 `pr-<N>`, localhost면 `local`이다.
     - 실행기는 로컬 결과만 만든다. PR 코멘트는 스킬(4번)이 단다.
     - #24(neon 크리틱)는 같은 맥에서 이 폴더의 스크린샷을 읽는다.

## Verification

- 격리: 매 실행의 stream-json `init` 이벤트에서 도구 목록이 위 허용 목록과 정확히 같다(`browser_snapshot`·`browser_evaluate` 없음). 실행기가 다르면 그 페르소나를 `실패(격리)`로 끝낸다. 플레이어 작업 폴더는 비어 있고 저장소 밖이다.
- 사전 확인(0번)은 로컬에서 끝낸다. 그다음 **이 PR의 Preview URL**로 3명을 동시에 한 번 돌린다. Preview는 PR마다 DO 저장소가 따로라, 첫 접속 때 첫 방문 보장으로 고장이 하나 있다.
  - 3명 모두 결과 폴더에 `report.md`와 스크린샷을 남긴다. 저장소 `git status`는 깨끗하다.
  - 폰 페르소나 2명의 스크린샷이 세로 모바일 비율이다.
