## 제안

1. 플랜 밖이지만 `gh api -X PUT repos/…/pulls/N/merge`와 GraphQL `mergePullRequest`·`enablePullRequestAutoMerge`는 머지 제한을 거치지 않는다. 서버 쪽 방어가 있으니 후속 과제로 둔다.

## 질문

1. Verification "pr-check: large + 예약 → 실패"는 누가 예약을 켜는가? 에이전트의 `gh pr merge 4 --auto`는 훅이 막는다(large). auto-merge는 draft에서 켤 수 없으므로 ready로 바꾼 뒤 사용자가 자기 터미널에서 켜고 끄는 것으로 보인다. Approve 전에 한다.
2. 전환 순서: 메인 체크아웃 동기화와 세션 재시작이 플랜에 4단계로 추가됐다. 열린 PR은 #4 하나뿐이고 워커가 열었다. 이 리포트 커밋도 Approve 전에 push해야 한다. 그 밖에 막히는 지점은 없다.
