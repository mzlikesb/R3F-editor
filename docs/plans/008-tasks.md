플랜 리뷰가 3턴을 넘었다(`46a93be` → `a728a80` → `5eeee86` → `34af0d2`). 그 뒤 지적은 플랜 파일을 고치지 않고 아래 수용 기준으로 넘긴다(`AGENTS.md` 3턴 규칙). 플랜 본문과 이 절이 다르면 **이 절이 이긴다**.

### R1. 하늘과 안개는 같은 PR에서 바꾼다 (neon 4턴 막는 문제 1)

- B.2(하늘을 씬 배경으로)를 **008-1**로 옮긴다. 008-1이 먼저 배포돼도 하늘·안개·지면이 같은 렌더와 톤 매핑을 지나므로 지평선 이음새가 생기지 않는다.
- 정전 때 배경 보간은 할당 없이 한다. 그라디언트 텍스처 두 장(평상시·정전)을 미리 만들어 두거나, 작은 배경 셰이더의 uniform 하나만 바꾼다. 프레임마다 텍스처를 새로 만들지 않는다.
- 008-1 수용 기준: 평상시와 정전 스냅샷에서 지면–하늘 경계에 이음새가 없다.

### R2. 후처리 실패는 세 경로로 잡는다 (neon 4턴 막는 문제 2)

- **사전 확인**: 컴포저를 붙이기 전에 WebGL2와 반정밀 부동소수 렌더 타깃(`EXT_color_buffer_half_float` 또는 `EXT_color_buffer_float`)을 확인한다. 없으면 `plain`으로 간다.
- **import 거절**: 동적 `import()`의 Promise 거절은 `catch`에서 `postMode = plain`으로 바꾼다. ErrorBoundary에 맡기지 않는다.
- **렌더 중 예외**: 컴포저 마운트·렌더의 예외는 후처리 전용 ErrorBoundary가 잡는다. 첫 렌더 뒤 컴포저 렌더 타깃의 프레임버퍼 상태를 한 번 확인해, 완전하지 않으면 `plain`으로 바꾼다.
- 단위 테스트: 기능 없음, import 거절, 시간 초과, 프레임버퍼 불완전, 이 네 경우 모두 `plain`과 렌더러 톤 매핑 켬으로 간다.

### R3. 품질 사다리는 후처리 축과 해상도 축을 나눈다 (neon 4턴 막는 문제 3)

플랜 B.6의 "0~4 다음에 5~7"을 아래로 바꾼다.

- **후처리 축(단방향)**: N8AO 끔 → Bloom 끔 → 컴포저 끔. 한 번 내려가면 세션 안에서 다시 켜지 않는다.
- **해상도·지오메트리 축(양방향, 기존 0~4)**: 지금 규칙(`DROP_GAIN`, 바닥, 백오프) 그대로다.
- **내려가는 순서**: FPS가 낮으면 ① N8AO 끔 → ② 기존 0~4 → ③ Bloom 끔 → ④ 컴포저 끔. 비용이 가장 큰 N8AO를 해상도보다 먼저 내린다.
- 후처리 축이 내려간 뒤 여유가 생기면, 해상도 축은 기존 규칙대로 다시 올라갈 수 있다. 후처리 축만 잠긴다.
- 패스 전환: N8AO는 별도 패스라 `enabled`만 끈다(재구성 없음). Bloom을 뺄 때는 `EffectComposer`를 같은 자식 순서로 다시 구성한다. 이때 색수차 효과 참조는 다시 잡는다. 한 번 멈칫하는 것은 허용한다.
- 단위 테스트: 위 순서대로 내려가고, 후처리 축은 올라가지 않으며, 해상도 축은 회복한다. `plain` 세션은 후처리 축을 건너뛴다.

### R4. 셰이크 우선순위와 정리 (neon 4턴 막는 문제 4)

- drei `CameraControls`는 `useFrame` 우선순위 `-1`로 갱신한다(`node_modules/@react-three/drei/core/CameraControls.js`). 셰이크는 **`-2`에서 직전 오프셋을 빼고, `0`에서 새 오프셋을 더한다.**
- 우선순위 `0`의 다른 훅(안개 거리 갱신 등)은 카메라 위치를 쓰지 않거나, 셰이크 크기(수 cm)를 무시해도 되는 것만 둔다.
- 언마운트되거나 `prefers-reduced-motion`이 켜질 때, 마지막으로 더한 오프셋을 즉시 뺀다(cleanup).
- 단위 테스트: 더하기·빼기 짝이 맞아 N프레임 뒤 카메라 위치가 셰이크 없는 경우와 같다. 중간에 언마운트해도 같다.

### R5. #85 측정 전제 (Codex P2 `34af0d2`, neon 4턴 제안 1)

- 기지를 **80초 이상** 비운 뒤 들어간다. 시작 전 `/api/base`로 고장 2개·정전 아님을 확인했을 때만 D.3의 1분 판정을 적용한다. 아니면 다시 잰다.

- 판정 뒤 `docs/content-plan.md`에 결과를 적고 #85를 닫는 일은 008-1 PR이 맡는다.

### R6. 그 밖의 수용 기준 (neon 4턴 제안 3~5)

- 색수차 발동 판정은 순수 함수(`chromaPulse(prev, next, source)`)로 둔다. 테스트: 라이브 정상→정전이면 발동한다. 스냅샷·재연결로 정전을 받으면 발동하지 않는다. 정상에서 끊겼다가 정전 중에 재연결한 경우도 발동하지 않는다.
- PerfHud에서 장면 드로우콜과 후처리 드로우콜을 나눠 보여준다. 008-2가 맡는다. 렌더 패스 직후의 `gl.info.render.calls`를 장면 값으로 쓴다.
- `plain` 경로 통과 기준: 선택 링·아웃라인이 보이고, 화면 전체가 지나치게 어둡거나 하얗게 날아가지 않는다. `toneMapped: false` 5종의 밝기 차이는 허용한다.
- hull 아웃라인은 `depthWrite: false`, `toneMapped: true`로 둔다. 선택 링·아웃라인 색은 Bloom 임계값 아래에 둔다. 5개 모듈 GLB 모두에서 확대가 메시 중심 기준으로 맞는지 스냅샷으로 확인한다.
- 오프셋 0 색수차의 평소 비용을 기준 기기 하한에서 재서 PR 본문에 적는다.
