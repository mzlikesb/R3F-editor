## Context

M1의 기지는 검은 화면 속 큐브 하나다. 플레이테스트(#30)에서 페르소나 3명은 홀드 수리 손맛은 좋다고 했다. 하지만 다음 문제를 짚었다.

- "이게 뭔지 모르겠다", "고장이 사이트 오류처럼 보인다"(#37)
- "다른 사람이 안 보인다"(#36)
- "수리하면 끝"(#38)
- "큐브가 배경에 묻힌다"(#39)

neon 아트 크리틱은 "수리 순간 3D 반응이 없다"(#42)를 더했다.

이 PR은 큐브를 **행성 위의 기지**로 바꾼다. 지금 있는 한 번의 수리가 누가 했는지 보이고, 손에 남게 한다. 서버 규칙(고장 1개, 발전기만)은 그대로이고, 모듈 여러 개의 고장·센서는 M3다.

경험 원칙: 1(다른 사람이 보인다), 3(들어오자마자 안다), 4(손맛), 5(폰 기준).

## 만들 것

### A. 기지 장면 (#39, #37 일부)

1. **모델**: CC0 로우폴리 SF 팩(Kenney Space Kit)에서 모듈 5종을 고르고, 행성 지면·바위 몇 개를 더한다.
   - 모듈: 발전기·산소·온실·통신탑·거주 돔
   - 출처는 `CREDITS.md`에 적는다.
2. **Draco**: `scripts/compress.sh`가 원본 GLB(커밋 안 함, `assets-src/`는 gitignore)를 `@gltf-transform/cli`로 Draco 압축해 `public/models/*.glb`를 만든다.
   - 디코더는 `public/draco/`에 셀프호스트한다. `useGLTF(url, '/draco/')`로 지정한다.
   - dev 의존성은 `@gltf-transform/cli` 하나를 추가한다.
   - 압축 전후 용량은 PR 본문에 적는다.
3. **배치**: 발전기를 가운데, 나머지 4개를 둘레에 둔다.
   - 수리할 수 있는 건 발전기뿐이다. 나머지는 정상 상태로 서 있는 배경 모듈이다(M3에서 살아난다).
   - 모듈 컴포넌트 `scene/Module.tsx`는 `moduleId`·상태를 받는 공용 형태로 만들어, M3에서 고장 대상이 늘어도 그대로 쓴다.
4. **조명**: 셀프호스트한 Poly Haven CC0 HDRI(1k, `public/hdri/`)를 `Environment`로 쓴다(외부 CDN 금지).
   - 그 위에 directional(그림자 1개) + 약한 ambient를 둔다. 정상 모듈의 어두운 면이 배경과 구분돼야 한다.
   - 배경은 순검정이 아닌 어두운 하늘색 그라디언트에 별 몇 개를 둔다.
5. **카메라**: drei `CameraControls` 하나로 궤도 조작과 선택 포커스를 한다.
   - 모듈을 누르면 그 모듈로 부드럽게 이동하고, 빈 곳을 누르면 전체 시점으로 돌아온다.
   - 폰에서 홀드할 때 카메라가 돌지 않게 하는 기존 동작은 유지한다.

### B. 상태가 한눈에 (#37, #42)

6. **상태 구분은 색만으로 하지 않는다**:
   - 고장: 붉은 emissive 펄스 + 경고 아이콘 배지 `⚠ 발전기 고장 · 눌러서 수리`(사이트 오류로 안 읽히게 모듈 이름 포함)
   - 정상: 차분한 머티리얼 + 은은한 상태등(녹색 점)
   - 고장이 정상보다 "밝기만 더한" 상태가 되지 않게, 정상 모듈도 HDRI·림 조명으로 형태가 보이게 한다.
7. **이름표**: 모든 모듈 위에 작은 이름표를 상시 표시한다(`<Html>`, 폰에서 겹치지 않는 크기). 고장·선택 모듈만 배지가 커진다.
8. **첫 화면 어포던스**: 고장 모듈 주변에 바닥 링이 맥박처럼 퍼진다. 첫 탭 전까지 화면 아래에 한 줄 힌트 `고장 난 모듈을 눌러 보세요`를 띄우고, 한 번 누르면 사라진다.

### C. 손맛 (#42)

9. **수리 완료 순간**: 흰 플래시, 스케일 펀치(스프링, `maath/easing`), 스파크 파티클(InstancedMesh 풀, 한 번에 1 드로우콜), 짧은 블룸 강화(`@react-three/postprocessing` Bloom)를 넣는다.
   - 모바일은 블룸 해상도를 낮추고, 파티클 수를 줄인다.
10. **색 웨이브**: 빨강에서 초록으로 바뀔 때 emissive가 아래에서 위로 훑는다.

### D. 다른 사람이 보인다 (#36, #38)

11. **남의 수리**: 내가 누르지 않았는데 `repaired`가 오면 모듈에서 링 핑이 퍼진다. 패널·토스트에 `누군가 발전기를 고쳤어요`를 띄운다. 내가 고쳤으면 `내가 고쳤어요 +1`이다.
    - 구분은 클라이언트의 홀드 상태(pending이었나)로 한다. 서버 메시지는 바꾸지 않는다.
12. **HUD 문구**: `함께 고친 횟수 N회 · 지금 N명이 같이 지키는 중 · 연결됨`으로 바꿔 뜻이 바로 읽히게 한다. 누적 수리 숫자는 롤링 카운트업으로 올라간다.
13. **수리 뒤**: 정상일 때 HUD 아래에 `기지 정상 가동 중 · 고장이 나면 여기에 알려 드려요`를 띄우고, 다른 모듈을 눌러 보면 이름과 `정상`이 보인다.
    - 재고장이 오면 토스트 `발전기가 다시 고장 났어요`와 배지가 뜬다.
    - 다음 고장 시각은 보여 주지 않는다(서버 규칙상 무작위, 기다림을 숙제로 만들지 않는다).

### E. 성능 HUD

14. `?perf` 쿼리나 HUD 토글로 FPS·드로우콜·삼각형(`gl.info.render`)을 보여 준다. 수치는 PR 본문 성능 예산에 적는다.
