## Context

M1의 기지는 검은 화면 속 큐브 하나다. 플레이테스트(#30)에서 페르소나 3명은 홀드 수리 손맛은 좋다고 했다. 하지만 다음 문제를 짚었다.

- "이게 뭔지 모르겠다", "고장이 사이트 오류처럼 보인다"(#37)

이 PR은 큐브를 **행성 위의 기지**로 바꾼다. 지금 있는 한 번의 수리가 누가 했는지 보이고, 손에 남게 한다. 서버 규칙(고장 1개, 발전기만)과 DO 저장 형식은 그대로이고, 모듈 여러 개의 고장·센서는 M3다. 서버 변경은 `repaired`에 "이 수리를 요청한 소켓인가"를 담는 것 하나다.

경험 원칙: 1(다른 사람이 보인다), 3(들어오자마자 안다), 4(손맛), 5(폰 기준).

## 만들 것

### A. 기지 장면 (#39, #37 일부)

1. **모델**: CC0 로우폴리 SF 팩(Kenney Space Kit)에서 모듈 5종을 고르고, 행성 지면·바위 몇 개를 더한다.
   - 모듈: 발전기·산소·온실·통신탑·거주 돔
   - **먼저 확인한다(구현 첫 작업)**: Kenney Space Kit에 5종이 각각 한 덩어리 GLB로 있는지, 모듈마다 머티리얼을 복제해 emissive를 따로 바꿀 수 있는지 본다. 파츠만 있으면 코드에서 파츠를 묶어 모듈을 만들고, 그것도 어색하면 다른 CC0 팩(Quaternius 등)으로 바꾼다. 바꾸면 PR 코멘트로 알린다.
   - 출처는 `CREDITS.md`에 적는다. 고른 원본 파일 이름과 다운로드 URL·버전은 `CREDITS.md`와 `scripts/compress.sh`의 목록에 같이 적어, 다른 worktree에서 `scripts/compress.sh`만 돌리면 같은 결과가 나오게 한다.
2. **Draco**: `scripts/compress.sh`가 원본 GLB(커밋 안 함, `assets-src/`는 gitignore)를 `@gltf-transform/cli`로 Draco 압축해 `public/models/*.glb`를 만든다.
   - **산출물은 커밋한다**: `public/models/*.glb`(Draco 압축본), `public/hdri/`, `public/draco/`. 빌드·CI는 외부 URL에 기대지 않는다. 원본(`assets-src/`)만 커밋하지 않는다.
   - `test:hooks`에 `public/draco/`가 설치된 `three`의 디코더와 같은지 비교하는 검사를 넣는다. `three`를 올리면 이 검사가 실패하고, `scripts/compress.sh --draco`로 다시 복사한다.
   - 디코더는 `public/draco/`에 셀프호스트한다. `useGLTF(url, '/draco/')`로 지정한다. 디코더 파일은 설치된 `three`의 `examples/jsm/libs/draco/gltf/`에서 스크립트가 복사해 버전이 항상 맞는다.
   - **새 의존성은 dev 의존성 `@gltf-transform/cli` 하나다.** `drei`(`CameraControls`·`Environment`·`<Html>`·`useGLTF`), `maath`는 이미 런타임 의존성이다. `@react-three/postprocessing`은 이미 설치돼 있지만 이 PR에서는 쓰지 않는다(아래 C.9).
   - 압축 전후 용량은 PR 본문에 적는다.
3. **배치**: 발전기를 가운데, 나머지 4개를 둘레에 둔다.
   - 수리할 수 있는 건 발전기뿐이다. 나머지는 정상 상태로 서 있는 배경 모듈이다(M3에서 살아난다).
   - 모듈 컴포넌트 `scene/Module.tsx`는 `moduleId`·상태를 받는 공용 형태로 만들어, M3에서 고장 대상이 늘어도 그대로 쓴다.
4. **조명**: 셀프호스트한 Poly Haven CC0 HDRI(512px `.hdr`, 0.5MB 안팎, `public/hdri/`, 출처는 `CREDITS.md`)를 `Environment`로 간접광에만 쓴다(외부 CDN 금지, 배경으로 쓰지 않는다).
   - 그 위에 directional(그림자 1개) + 약한 ambient를 둔다. 정상 모듈의 어두운 면이 배경과 구분돼야 한다.
   - 배경은 순검정이 아닌 어두운 하늘색 그라디언트에 별 몇 개를 둔다.
   - **용량과 로딩**: 정적 에셋(GLB 5종+지면·바위, HDRI, Draco 디코더) 합계 **3MB 이하**. 넘으면 HDRI를 줄이거나 모델 수를 줄인다.
     - 로딩 중에는 `Suspense` fallback으로 HUD와 `기지를 불러오는 중…`을 보여 준다. 검은 빈 화면을 두지 않는다. WS 연결과 수리 패널은 로딩과 무관하게 동작한다.
     - 에러 경계는 둘로 나눈다. HDRI가 실패하면 `Environment`만 빠지고 기본 조명(directional+ambient 강도 올림)으로 간다. 모듈 GLB가 실패하면 그 모듈만 기본 도형(발전기는 지금의 큐브)으로 바뀐다. 어느 쪽이든 수리는 계속 된다.
5. **카메라**: drei `CameraControls` 하나로 궤도 조작과 선택 포커스를 한다.
   - 모듈을 누르면 그 모듈로 부드럽게 이동하고, 빈 곳을 누르면 전체 시점으로 돌아온다. 드래그로 돌린 뒤 손을 뗀 것은 "빈 곳 누르기"로 보지 않는다(포인터 이동 거리 임계값).
   - 폰에서 홀드할 때 카메라가 돌지 않게 하는 기존 동작은 유지한다.
   - 제한: 지면 아래로 못 가게 `maxPolarAngle`, 줌 `minDistance`·`maxDistance`, 팬은 기지 반경 밖으로 못 나가게 한다. 폰에서는 모듈 포커스 때 하단 패널에 가리지 않게 시점을 위로 조금 띄운다.
   - 얇은 모듈(통신탑 등)은 보이지 않는 넉넉한 충돌 박스로 누르기 쉽게 한다.

### B. 상태가 한눈에 (#37, #42)

6. **상태 구분은 색만으로 하지 않는다**:
   - 고장: 붉은 emissive 펄스 + 경고 아이콘 배지 `⚠ 발전기 고장 · 눌러서 수리`(사이트 오류로 안 읽히게 모듈 이름 포함)
   - 정상: 차분한 머티리얼 + 은은한 상태등(녹색 점)
   - 고장이 정상보다 "밝기만 더한" 상태가 되지 않게, 정상 모듈도 HDRI·림 조명으로 형태가 보이게 한다.
7. **이름표**: 발전기는 상태와 관계없이 이름표를 상시 표시한다(고장이면 6의 배지). 나머지 모듈은 선택했을 때만 이름표를 띄운다. 폰에서 `<Html>` 겹침과 터치 방해를 줄이기 위해서다.
   - 이름표는 `pointer-events: none`이다. **고장 배지만 예외로 누를 수 있고**, 누르면 발전기를 선택한다(문구가 "눌러서 수리"이므로 배지 탭이 빈 곳 탭으로 새지 않게).
8. **첫 화면 어포던스**: 고장 모듈 주변에 바닥 링이 맥박처럼 퍼진다. 고장이 있을 때만 화면 아래에 한 줄 힌트 `고장 난 모듈을 눌러 보세요`를 띄운다. 아무 모듈이나 한 번 누르면 그 세션에서는 다시 뜨지 않는다.

### C. 손맛 (#42)

9. **수리 완료 순간**: 흰 플래시, 스케일 펀치(스프링, `maath/easing`), 스파크 파티클(InstancedMesh 풀, 1 드로우콜), 가산 블렌딩 글로우 스프라이트 하나를 넣는다. **후처리(Bloom)는 쓰지 않는다**(상시 GPU 패스·순간 마운트 스터터링을 피한다).
   - 터치 기기(`matchMedia('(pointer: coarse)')`)는 파티클 수를 절반으로 줄인다.
10. **상태 전환**: 빨강에서 초록으로 바뀔 때 emissive를 보간하고, 바닥에서 위로 올라가는 링 메시가 모듈을 한 번 훑는다(커스텀 셰이더 없음). 이건 누가 고쳤든 항상 돈다. 9의 플래시·펀치·파티클은 내가 고쳤을 때만, D.11의 링 핑(바닥에 수평으로 퍼지는 물결)은 남이 고쳤을 때만이다.

### D. 다른 사람이 보인다 (#36, #38)

11. **누가 고쳤나**: 서버가 `repaired`를 보낼 때 **수리를 실제로 반영시킨 요청의 소켓에만** `mine: true`를 담는다. 나머지 소켓에는 `mine: false`를 보낸다.
    - 동시에 둘이 눌러도 서버는 먼저 처리한 요청 하나만 반영한다(기존 멱등 규칙). 그래서 `mine: true`는 정확히 한 소켓에만 간다.
    - 소켓 구분은 참조 동일성에 기대지 않는다. 연결을 받을 때 소켓마다 무작위 id를 `serializeAttachment`로 붙이고(하이버네이션 뒤에도 남는다), 브로드캐스트에서 요청 소켓의 id와 비교한다. id가 없는 소켓(배포 전에 열린 연결 등)은 요청을 보냈든 받든 항상 `mine: false`다. 없는 id끼리 같다고 보지 않는다.
    - 진 탭은 pending이어도 `mine: false`를 받는다. 이때 `누군가 먼저 고쳤어요`(기존 beaten 문구)와 링 핑을 보여 준다.
    - 아직 누르고 있는 중(holding, 요청 전)에 `repaired`가 오면 기존대로 홀드를 풀고 `누군가 먼저 고쳤어요`와 링 핑을 보여 준다. 홀드하지 않던 사람(idle)은 `누군가 발전기를 고쳤어요`다.
    - `mine: true`면 `내가 고쳤어요 +1`과 C의 손맛 연출을 보여 준다. `mine: false`면 링 핑과 토스트 `누군가 발전기를 고쳤어요`를 보여 준다.
    - `shared/protocol.ts`의 파서는 `mine`이 없으면 `false`로 본다(옛 클라이언트·서버 호환). DO 저장 형식은 바뀌지 않는다.
    - 수리를 보낸 직후 `repaired`를 받기 전에 끊기면, 재연결 스냅샷으로 상태만 맞춘다(내 수리 연출은 생략한다).
12. **HUD 문구**: 두 줄로 쓴다. 윗줄 `함께 고친 횟수 N회`, 아랫줄 `지금 N명이 같이 지키는 중`(혼자면 `지금은 나 혼자 지키는 중`)과 연결 상태(끊기면 `재연결 중…`). 숫자가 바뀌면 잠깐 커졌다 돌아오는 강조만 한다(카운트업 애니메이션은 하지 않는다).
    - 화면 배치 우선순위: 위는 HUD, 아래는 패널 > 토스트 > 힌트(동시에 뜨면 위의 것이 자리를 갖고, 아래 것은 패널 위로 밀린다).
13. **수리 뒤**: 정상일 때 HUD 아래에 `기지 정상 가동 중 · 고장이 나면 여기에 알려 드려요`를 띄우고, 다른 모듈을 눌러 보면 이름과 `정상`이 보인다.
    - 정상에서 고장으로 바뀌면 토스트 `발전기가 다시 고장 났어요`와 배지가 뜬다. 처음 접속했을 때 이미 고장이면 토스트는 띄우지 않는다(배지와 힌트만).
    - 발전기가 고장 난 채 다른 모듈을 선택하면 패널에 그 모듈 이름과 `정상`이 뜨고, 패널 아래에 `발전기 고장 — 눌러서 이동` 버튼이 남는다.
    - 다음 고장 시각은 보여 주지 않는다(서버 규칙상 무작위, 기다림을 숙제로 만들지 않는다).
