# 007 — 넓은 행성, 가벼운 화면: 인스턴싱·LOD·적응형 품질

- 브랜치: `feat/007-perf`
- 등급: large
- 관련 이슈: 없음
- 마일스톤: M4 성능
- 상태: 플랜 리뷰

## Context

지금 기지는 모듈 5개와 바위 몇 개가 있는 원판이다. 드로우콜은 35~38로 예산 안이지만, 화면 밖은 비어 있다. 행성이라기보다 무대처럼 보인다.

이 PR은 기지 둘레를 **수천 개의 오브젝트**로 채운다. 그래도 드로우콜·프레임은 예산 안에 둔다.

- 태양광 패널 밭: 발전기 둘레의 의미 있는 배경. 정전이면 같이 꺼진다
- 흩어진 바위와 돌
- 하늘을 천천히 도는 소행성대

폰에서는 기기 성능에 맞춰 품질을 스스로 낮춘다. 번들 크기 예산은 이번에 실측 기준선으로 확정해 CI에서 강제한다(`AGENTS.md` 성능 예산).

경험 원칙: 2(기지는 계속 살아 있다 — 하늘이 움직이고 패널이 정전에 반응한다), 5(폰이 기준 화면이다).

## 만들 것

### A. 인스턴싱 (drei `Instances` / `InstancedMesh`)

1. **배치는 결정적이다**: 시드 하나로 만드는 순수 함수 `scatter(seed, count, rule)`가 위치·회전·크기를 돌려준다(`src/scene/scatter.ts`, 테스트).
   - 규칙: 기지 반경과 모듈 둘레의 빈 땅(탭 상자·바닥 링 영역)은 비운다. 겹침을 최소 간격으로 거른다.
   - 모든 접속자가 같은 풍경을 본다. 서버 상태는 아니다.
2. **태양광 패널 밭**: 발전기 반대편 바깥 고리에 패널 약 600개. 같은 GLB 하나(Kenney Space Kit에 패널이 있으면 그것, 없으면 코드 박스)를 인스턴스로 그려 **드로우콜 1개**(그림자 포함 2개)로 만든다.
   - 정전이 되면 패널의 발광(작은 파란 반사)이 꺼지고, 복구되면 발전기에서 먼 순서로 켜진다. 인스턴스 색 버퍼 한 번 갱신으로 처리한다.
3. **바위·돌**: 기존 바위 3종 GLB를 각각 인스턴스로 그려 합계 약 1,500개(종류당 드로우콜 1개)로 만든다. 탭을 받지 않는다(raycast 끔).
4. **소행성대**: 하늘 높이 고리 모양으로 작은 바위 약 1,500개를 둔다. 고리 전체를 한 그룹으로 천천히 회전시킨다(인스턴스 행렬은 처음 한 번만 쓰고, 매 프레임에는 그룹 회전만 바꾼다). 드로우콜 1개, 그림자 없음.
5. 인스턴스 메시들은 `frustumCulled`를 그룹 경계로 맞춘다. 카메라 밖이면 통째로 건너뛴다.

### B. LOD (drei `Detailed`)

6. 바위·패널은 거리 3단계로 그린다. 가까우면 원본, 중간이면 단순화 메시(`gltf-transform simplify`로 빌드 때 만든다), 멀면 숨긴다.
   - 인스턴스 그룹 단위로 고리를 나눠(안쪽·바깥쪽 링 셀) 셀마다 `Detailed`를 쓴다. 인스턴스마다 LOD를 쓰지 않는다.
   - 단순화 메시도 `scripts/compress.sh`가 만들고 Draco로 압축해 커밋한다.

### C. 적응형 품질

7. **`PerformanceMonitor`**(drei): FPS가 떨어지면 단계적으로 품질을 낮춘다.
   - 단계: dpr(2 → 1.5 → 1) → 그림자 해상도 반으로 → 그림자 끔 → 소행성대 절반 → 바위 바깥 링 숨김
   - 올라가면 반대로 되돌린다. 바뀔 때마다 깜빡이지 않게 1초 이상 간격을 둔다.
   - 지금 단계는 `?perf` HUD에 보인다.
8. **처음 단계**: 터치 기기(`pointer: coarse`)나 화면이 작으면 dpr 1.5·그림자 반해상도에서 시작한다. 데스크톱은 최고 단계에서 시작한다.
9. 지금 있는 것은 유지한다: 수리 연출 파티클 수 절반(터치), 블룸 없음.

### D. 번들 예산 확정

10. 지금 실측(초기 JS gzip 약 377KB)을 기준선으로 **예산 450KB**를 `scripts/bundle-budget.sh`로 CI에서 실패 처리한다(빌드 후 `dist/assets/*.js` gzip 합계). 여유분은 M5 이펙트용이다.
    - 정적 에셋(GLB·HDRI·디코더) 합계 예산 3MB도 같은 스크립트에서 확인한다.
    - 넘으면 이유를 본문에 적고 사용자 판단으로 통과(`AGENTS.md` 규칙). 그 경우 예산 값을 바꾸는 커밋이 PR에 함께 들어간다.
11. `AGENTS.md` 성능 예산 절의 "잠정치·확정 전 CI는 경고만" 문구를 확정 값으로 바꾼다.

### E. 실측 기록

12. `?perf` HUD에 드로우콜·삼각형·FPS·품질 단계·dpr을 보인다(지금 있는 HUD에 단계와 dpr만 더한다).
13. PR 본문에 다음을 적는다:
    - 데스크톱(헤드리스는 참고값)과 사용자 실기 폰의 FPS
    - 드로우콜(전체 시점, 포커스, 정전, 수리 연출 순간)
    - 삼각형 수
    - 번들·에셋 크기
    - 인스턴싱 전후 비교: 같은 수를 개별 메시로 그렸을 때의 드로우콜(로컬 측정, 코드에는 남기지 않는다)

## Verification

- `format:check`·`lint`·`typecheck`·`npm test`·`test:worker`·`test:hooks`·`build`·`bundle-budget`가 통과한다.
- `scatter` 테스트:
  - 같은 시드는 같은 결과다.
  - 금지 영역(기지 반경, 모듈 탭 상자, 바닥 링)과 겹치지 않는다.
  - 최소 간격을 지킨다.
- `?perf`(로컬, 1280×800·390×844) 드로우콜:
  - 전체 시점에서 오브젝트 수천 개를 더해도 **60 이하**(지금 35~38에서 인스턴스 그룹만큼만 는다)
  - 정전·고장 3개·수리 연출 순간에도 100 이하
- 품질 단계: 개발용 강제 프레임 저하(`?perf&degrade`)로 단계가 순서대로 내려가고, 풀면 다시 올라간다. 단계가 바뀔 때 화면이 깜빡이지 않는다.
- 정전이면 패널 발광이 꺼지고, 복구되면 순차로 켜진다.
- 바위·패널·소행성을 눌러도 모듈 선택이나 빈 곳 판정이 바뀌지 않는다(raycast 꺼짐). 모듈 탭은 그대로 된다.
- 번들 예산: 예산을 일부러 낮추면 CI가 실패한다(로컬 확인).
- 사용자 실기: 중급 폰에서 Preview `?perf`가 30fps 이상이고, 품질 단계가 어디서 멈추는지 기록한다.
- Preview 페르소나 플레이테스트(동시 3명) + neon 아트 크리틱: 풍경이 기지를 가리거나 고장 표시를 묻지 않는지 본다.
