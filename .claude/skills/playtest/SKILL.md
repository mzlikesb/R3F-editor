# 플레이테스트

규칙의 원본은 `AGENTS.md`다(이슈·라벨·마일스톤, 경험 원칙). 이 스킬은 순서와 명령만 담는다. 설계는 `docs/plans/004-playtest.md`.

입력: PR 번호 `N`.

## 1. 실행

그 PR의 Preview URL(`https://pr-N-outpost.<계정>.workers.dev`)로 돌린다. **production URL로는 돌리지 않는다**(실제 접속자 수와 기지 상태를 건드린다. 실행기도 거절한다).

```
scripts/playtest.sh https://pr-N-outpost.<계정>.workers.dev
```

- 기본은 3명 동시다. 한도·부하로 실패하면 `--serial`로 다시 돌린다
- 페르소나만 고르려면 URL 뒤에 이름을 준다(`phone-casual`, `pc-dev`, `first-visitor`)
- 마지막 줄이 결과 폴더(`~/.local/share/outpost-playtests/pr-N-<시각>/`)다. 안에 페르소나별 `report.md`(머리에 상태·실행 모드·기기·시간·토큰)와 스크린샷이 있다. 저장소에 커밋하지 않는다. 실행기는 홈을 `~`로 줄여 찍는다
- 종료 코드 1이면 일부가 `실패(사유)`다. 나머지는 그대로 읽는다

## 2. 읽고 이슈로 올리기

1. 페르소나별 `report.md`를 읽는다. 접속했을 때 고장이 없었거나 다른 페르소나가 먼저 고친 것도 있는 그대로의 관찰이다
2. 지적을 `AGENTS.md`의 경험 원칙과 대조한다. 같은 지적이 둘 이상이면 하나로 묶는다
3. 실행 모드가 `순차`이거나 시차가 커서 동시 접속이 없었으면 "혼자인 것 같았다"는 원칙 1 위반 이슈로 올리지 않고 요약에만 적는다
4. 이슈는 `gh issue create --body-file <파일>`로 올린다. 라벨 `playtest`와 그 PR의 마일스톤을 붙인다. 본문 형식:
   - 맨 위 `결정할 것` 줄(없으면 `결정할 것: 없음`)
   - 어느 페르소나가 무엇을 보고 막혔나(리포트 인용)
   - 관련 원칙(번호)
   - 대상 PR 번호
   - 근거 스크린샷 파일 이름과 로컬 폴더 경로
5. PR·이슈에 결과 폴더 경로를 적을 때 홈은 `~`로 줄인다(`/Users/<이름>`을 노출하지 않는다)
6. 지적이 하나도 없으면 이슈는 올리지 않고 요약 코멘트에 "지적 없음"으로 남긴다

## 3. PR에 요약 코멘트

`gh pr comment N --body-file <파일>`로 단다. 이것이 공유되는 기록이다.

- 페르소나별 한 줄(상태와 핵심 지적)
- 올린 이슈 번호(또는 "지적 없음")
- 실행 모드, 페르소나별 시간과 토큰(리포트 머리에서 옮긴다. 금액은 적지 않는다)
- 결과 폴더 경로
- 페르소나별 리포트 본문을 `<details>`로 접어서 붙인다. 붙이기 전에 `@`를 `@`+ZWJ(U+200D)로 바꿔 멘션을 무력화한다(`scripts/neon-review.sh` 방식). 이슈에 리포트를 인용할 때도 같다

같은 PR에서 고친 뒤 다시 돌리면 1~3을 처음부터 다시 한다(새 결과 폴더, 새 코멘트).
