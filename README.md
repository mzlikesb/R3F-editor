## 무엇을 하는가

기지에는 모듈이 다섯 개 있다 — 발전기, 산소, 온실, 통신, 거주동. 모듈은 수십 초마다 하나씩 무작위로 고장난다. 고치는 게 할 일이다.

수리에는 **부품**이 한 개 든다. 부품은 기지 바닥에 10초마다 조각 하나로 떨어지고, 눌러서 주우면 모두가 함께 쓰는 창고에 쌓인다(최대 5개). 창고가 비면 수리는 거절되므로, 고장 사이사이에 조각을 주워 두는 게 준비다.

고장이 겹치다 상한에 닿으면 **정전**이 난다. 햇빛이 죽고 비상등만 남는다. 정전이 날 때는 발전기가 반드시 고장 목록에 있으므로 발전기를 고쳐야 불이 돌아오고, 복구된 빛은 발전기에서 바깥쪽으로 퍼진다.

서버는 기지를 **하나만** 들고 있다. 접속자가 몇 명이든 전부 같은 기지, 같은 고장을 본다. 다른 사람이 고치면 내 화면에서도 그 모듈이 초록으로 번지고, 같은 고장을 함께 누르고 있었다면 둘 다 고친 사람으로 기록된다.

아무도 없는 동안에도 기지는 삭는다. 다시 들어오면 비어 있던 시간만큼 고장이 쌓여 있다.

## 조작

| 하고 싶은 것 | 방법 |
| --- | --- |
| 모듈 선택 | 탭 / 클릭 |
| 시점 회전 | 드래그 |
| 줌 | 휠 / 두 손가락 |
| 부품 줍기 | 바닥의 조각 탭 |
| 수리 | 패널의 수리 버튼을 1초간 누른 채로 (부품 1개 소모) |
| 선택 해제 | 빈 곳 탭 |
| 기지 기록 | 화면 위 HUD 탭 (가동 시간, 정전 이력) |

HUD에 현재 가동 시간, 공용 창고의 부품 수(`기지 창고 3/5`), 접속자 수, 총 수리 횟수, 마지막 수리가 뜬다. 주소에 `?perf`를 붙이면 FPS·드로우콜·삼각형 수·품질 단계 HUD가 켜진다.

## 어떻게 만들었나

### 서버: Durable Object 하나가 전부다

데이터베이스도, 게임 루프도 없다. Cloudflare Worker는 `/ws`와 `/api/*`만 가로채 **이름이 항상 `base`인 Durable Object 하나**로 넘긴다. 그래서 전원이 같은 객체에 모인다.

Durable Object는 단일 스레드라 두 사람이 같은 고장을 동시에 눌러도 락이 필요 없다. 메시지가 큐로 직렬화돼 들어오고, `repair()`가 두 번째 호출에서 `null`을 돌려주면 그게 곧 "이미 고쳐짐"이다. 상태는 키 하나에 객체 한 덩이로 저장한다.

고장 발생기는 타이머 루프가 아니라 **알람**이다. 다음 고장 시각에 `setAlarm`을 걸고 객체는 잠든다(hibernation). 소켓은 열려 있지만 메모리에서 내려가고, 알람이나 메시지가 올 때만 깨어난다. 하트비트도 런타임이 대신 응답해 객체를 깨우지 않는다.

잠든 사이의 시간은 **역산한다.** 접속자가 0에서 1이 될 때 마지막 저장 시각부터 지금까지 몇 번의 고장 주기가 지났는지 계산해 그만큼 고장을 꽂는다. 새로고침으로 수리 횟수를 농사하지 못하게 하는 최소 무인 시간과, 혼자 들어와 바로 정전을 보지 않게 하는 상한이 함께 걸려 있다.

규칙은 모두 순수 함수(`worker/state.ts`)로 빼 두고 I/O만 Durable Object 클래스가 한다. 시각·난수·ID를 인자로 주입하므로 규칙 전체를 함수 단위로 테스트한다.

### 클라이언트: 로직과 그림을 나눴다

세 층이다. 맨 아래는 **순수 함수** — 메시지 파서, 수리 버튼 상태 머신, 품질 사다리, 배치 좌표, 피드백 분류. 가운데는 zustand 스토어 하나. 맨 위가 React와 R3F 컴포넌트이고, 이 층은 스토어를 읽어 그리는 일만 한다. 진입점은 컴포넌트를 쌓는 것 외에 아무것도 하지 않는다.

클라이언트와 서버가 주고받는 메시지 타입과 파서는 `shared/protocol.ts` 한 파일에 있고 양쪽이 같은 파일을 쓴다. 들어오는 모든 메시지는 손으로 쓴 파서를 통과해야 하며, 읽을 수 없는 프로토콜 버전을 만나면 수리를 잠그고 새로고침 배너를 띄운다.

### 3D

모델은 GLB를 Draco로 압축해 올리고 `useGLTF`로 읽는다. 모듈마다 Suspense와 에러 경계가 따로 있어 하나가 느리거나 깨져도 나머지는 그려진다. 같은 격납고 계열을 쓰는 온실과 거주 돔은 머티리얼 클론에 다른 틴트를 입혀 이름표 없이도 구분되게 했다.

배경은 별이 뜬 씬 하늘이고, 멀리 갈수록 지면이 하늘색으로 안개에 묻힌다. 정전 때 안개도 조명과 같이 어두워진다. 모든 기기가 같은 후처리 스택(N8AO, Bloom, 색수차, 비네트, 노이즈, 톤매핑, SMAA)을 거치며, 느린 기기만 위 사다리로 단계를 내린다.

조명은 그림자를 지는 directional 하나와 약한 ambient, 그리고 **배경이 아니라 간접광으로만 쓰는 HDRI**다. HDRI를 못 읽으면 경계가 직접광을 올려 씬을 살린다. 정전 때는 조명 레벨을 프레임마다 보간하는데, 어두워지는 속도보다 복구 속도를 느리게 줬다 — 불이 들어오는 게 보여야 하니까.

선택은 보이는 메시가 아니라 **안 보이는 판정 박스**가 받는다. 모델 실루엣이 복잡해도 터치 판정이 일정하다. 손을 뗀 위치와 누른 위치의 거리를 재서 궤도 회전과 탭을 구분하므로, 돌리다 뗀 것이 선택 해제로 오인되지 않는다. 선택한 모듈에는 바닥 링이 깔리고 실루엣을 따라 inverted hull 아웃라인이 둘러진다(Outline 패스는 쓰지 않는다). 선택하면 카메라가 그 모듈로 부드럽게 붙고, 화면 비율에 따라 시야각과 거리를 다시 계산해 세로 화면 폰에서도 다섯 모듈이 전부 들어온다.

### 성능

바위밭과 태양광 패널밭, 소행성대는 `InstancedMesh`로 그린다. 바위는 셀로 나눠 **셀 단위 LOD**를 적용한다 — 가까운 셀은 원본 지오메트리, 먼 셀은 단순화한 메시와 평면 셰이딩 머티리얼 하나로 바꿔 셀·종류·레벨마다 드로우콜 하나만 쓴다. 패널 램프는 인스턴스별 색을 매 프레임 갱신해 따로 깜빡인다.

FPS는 `gl.info.render`를 읽어 자체 HUD에 띄운다(`?perf`). 거기에 적응형 품질 사다리가 붙어 있다. 측정값을 링 버퍼에 모아 단계를 올리고 내리는데, 복귀 임계값에 갇히는 문제를 막는 주기적 재시도, 실패 시 지수 백오프, **프레임이 캡된 기기 감지**(단계를 내렸는데 FPS가 충분히 오르지 않으면 캡으로 보고 되돌린다)가 들어 있다. 사다리는 두 축이다. 해상도와 인스턴스 수 축은 셰이더 재컴파일이 없어 양방향으로 오르내린다. 후처리 축(N8AO, Bloom, 컴포저 순으로 끈다)은 패스를 다시 구성하느라 한 번 멈칫할 수 있어 한 방향으로만 내려가고, 세션 안에서 되돌아오지 않는다. 그림자 맵 크기는 시작 시 기기 등급으로 고정한다.

번들과 정적 에셋 크기는 CI에서 예산을 넘기면 실패한다. 폰과 PC 해상도 스크린샷은 자동으로 찍어 확인한다.

## 로컬에서 돌리기

```bash
npm ci
```

Worker와 Durable Object까지 포함해 한 번에 띄우려면:

```bash
npm run preview
```

HMR을 쓰며 개발할 때는 터미널 두 개를 쓴다. `npm run dev`는 클라이언트만 띄우고 `/ws`와 `/api`는 8787로 프록시하므로, wrangler를 따로 띄워야 실시간 통신이 붙는다. `wrangler.jsonc`가 정적 에셋 폴더로 `./dist`를 가리키고 그 폴더는 커밋되지 않으니, wrangler를 처음 띄우기 전에 한 번 빌드한다.

```bash
npm run build && npx wrangler dev
```

```bash
npm run dev
```

검사:

```bash
npm test && npm run typecheck && npm run lint
```
